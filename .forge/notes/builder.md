# Builder addendum (this repo)

**Engine code treats its inputs as hostile.** Most security-lens send-backs here are the same few holes. Before you report done on anything in `lib/` that reads job state, repo files, git or `gh` output, or config:
- **git and gh**: put `--` before revisions and paths, and validate values that come from `gh` or job state before they reach argv (a commit SHA matches `/^[0-9a-f]{40}$/`). Start git only through `git()`/`gitSpawnSync()` in `lib/integrations/git/runner.ts`, and spread `PINNED_DIFF_OPTS` or `STATUS_ARGV` when you parse its output; `test/invariants/security-scan.test.ts` enforces both.
- **paths**: a path from job.json, config or the worktree may be a symlink or a FIFO. Resolve it, then open with `O_NOFOLLOW | O_NONBLOCK` as `readRegular` in `lib/core/os/fs.ts` does. Before any recursive delete, check that the resolved path sits under the root you expect (the worktrees root or the job dir).
- **executables from config**: accept a bare name looked up on PATH or an absolute path outside the repo (`isClaudeExecutable` in `lib/core/os/process.ts` + `insideRepo` in `lib/core/config/trust.ts`), never a relative path or a basename match.
- **regexes**: `test/invariants/security-scan.test.ts` runs every `lib/` regex literal on 10k-character hostile lines, so keep yours linear.
Add one test per hole you close. Evidence: daemon-per-job-with-detailed-alva, daemon-supervisor-config-migration-and-roz1, 1-verify-reports-test-integrity-deleted, 17-measure-the-human-delta-after, 7-eval-worktrees-leak-the-solution, 4-wave2-ac-ui-proof-model-diversity. (added 2026-10-13)
