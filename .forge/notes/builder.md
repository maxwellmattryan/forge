# Builder addendum (this repo)

**Engine code treats its inputs as hostile.** Most security-lens send-backs here are the same few holes. Before you report done on anything in `lib/` that reads job state, repo files, git or `gh` output, or config:
- **git and gh**: put `--` before revisions and paths, and validate values that come from `gh` or job state before they reach argv (a commit SHA matches `/^[0-9a-f]{40}$/`). Start git only through `git()`/`gitSpawnSync()` in `lib/integrations/git/runner.ts`, and spread `PINNED_DIFF_OPTS` or `STATUS_ARGV` when you parse its output; `test/invariants/security-scan.test.ts` enforces both. Repo and worktree config, attributes and sparse checkout are all builder-writable. (edited 2026-10-29 · experiment: builder-hostile-input · review-by: 2027-01-29)
- **paths**: a path from job.json, config or the worktree may be a symlink or a FIFO. Resolve it, then open with `O_NOFOLLOW | O_NONBLOCK` as `readRegular` in `lib/core/os/fs.ts` does. Before any recursive delete, check that the resolved path sits under the root you expect (the worktrees root or the job dir). (edited 2026-10-29 · experiment: builder-hostile-input · review-by: 2027-01-29)
- **executables from config**: accept a bare name looked up on PATH or an absolute path outside the repo (`isClaudeExecutable` in `lib/core/os/process.ts` + `insideRepo` in `lib/core/config/trust.ts`), never a relative path or a basename match.
- **regexes**: `test/invariants/security-scan.test.ts` runs every `lib/` regex literal on 10k-character hostile lines, so keep yours linear. (edited 2026-10-29 · experiment: builder-hostile-input · review-by: 2027-01-29)
- **gates fail closed**: a check that clears a push, a merge, an approval or a line in an agent's brief passes only on a positive answer (`=== true`, an event that is present), never on `!== false`, so null, missing or unreadable state blocks. Decide it from state only the CLI writes (`job.json`, `events.jsonl`), never from a file a session can edit (`review/round-<n>/*.md`, `build.md`, the rest of the job dir), and check that the caller may act on that job and that gate. Test the missing-state case. Evidence: 380-fewer-agent-hops-on-a (null `reviewCurrent` passed a clean pass), 289-escalation-reasons-as-data-before-2 (lens escalation read from writable review files), 285-spec-approval-notes-reach-the-2 (approve-spec note wrote a builder hint unchecked), 573-open-the-pr-on-escalation (secrets hold read only the root scan). (added 2026-10-30 · experiment: builder-gates-fail-closed · review-by: 2026-11-27)
