# Dashboard security

**One server, many projects.** The machine dashboard serves every project in the machine index from one server, with one token, one port and one runtime record. Project endpoints live under `/api/p/<project>/<x>` (the `/api/<x>` paths below are written relative to that prefix): `GET /api/state` and every other bare project path answer 404. Machine endpoints keep top-level paths: the page (`/`, `/index.html`), `/assets/*`, `/forge.png`, `GET /api/about`, `GET /api/projects` (the registered projects, their job counts, latest job and pools, and the machine cap), `GET /api/projects/events` (its SSE stream, a `projects` frame on connect and on change) and `GET /api/projects/stats?days=7|30|90` (each loaded project's shipped jobs and cost per UTC day, names and numbers only; any other `days` is 400, so a crafted query can't widen the ledger reads, and the ledger is read without writing), each `/api` one behind the read guard. `POST /api/projects` (the dashboard's Add project, behind the token, Origin and JSON guard like every POST) registers a repo as `forge project add <path>` does: its body is exactly `{"path": string, "name"?: string}`, and a body with another key or a non-string value, a `path` that is empty, over 4096 characters, holds a NUL, CR or LF, or is neither absolute nor `~` / `~/…` (so never relative to the server's cwd or another user's `~bob`), or a non-empty `name` failing `PROJECT_NAME` is a 400 before any filesystem or git call. The path then resolves through `resolveProjectRoot` (`~` expanded, a worktree or subdirectory to its main checkout's realpath, `.forge/config.yml` required; git sees the path only as its `cwd`), and its refusals are a 400; a name another path holds, or a machine index this Forge can't read, is a 409 with the index untouched. The same repo again is `added: false` and writes nothing. It never approves the project's trusted files, so a project with `daemon.enabled: true` waits for a human's Start (docs/architecture/daemon-security.md). `lib/server/start.ts` holds two route tables, `ROUTES` (matched on the full path) and `PROJECT_ROUTES` (matched on the path after `/api/p/<project>`). Dispatch runs the loopback checks, matches a row, runs the POST guard and the row's guards, and only then resolves the project segment: it must match `PROJECT_NAME` (`^[a-z0-9][a-z0-9._-]{0,63}$`) before anything reads the index, then name a loaded project, after one re-read of the index on a miss; anything else is `404 {"error":"no registered project \"<name>\""}` (the name cut to 64 characters, JSON-escaped). So a cross-site or untokened request never reads the index, and `..`, `%2F`, uppercase or an overlong name never reaches another project. Job ids resolve only inside the project the path names: the same id in two projects is each project's own job, and `/file` and `/raw` confine to that project's job dir, so an absolute path, a `..` or a symlink into another project's files is refused like any outside path. Event streams are keyed `<project>/<scope>` in the machine's one client map, so a stream on one project's `_inbox` never gets another's frames, and `MAX_SSE_CLIENTS` (8) counts streams machine-wide, `/api/projects/events` included.

The server binds 127.0.0.1 only and answers only requests whose Host is a loopback name, which defeats DNS rebinding; before the Host check, dispatch also refuses a request whose socket peer is not a loopback address (IPv4 `127.0.0.0/8`, `::1` or `::ffff:127.x.x.x`) with 403 `not loopback`, defence in depth should the bind ever change. GETs are read-only, and every GET under `/api` takes the read guard: a foreign Origin is a 403 `bad origin` and a `Sec-Fetch-Site` other than `same-origin` or `none` is a 403 `cross-site`, so another site's no-cors GETs (`<img>`, `<script>`, `fetch` with `no-cors`, which carry no Origin and whose replies it can't read anyway) can't loop the expensive reads such as `/api/stats`. A request with neither header (curl, the CLI) is served as before. Only `/`, `/index.html`, `/assets/*` and `/forge.png` are served on the Host check alone. `GET /api/backlog?refresh` refetches from the tracker only when it carries the page's token in `x-forge-token` (compared in constant time); without it, or with a wrong one, `refresh` is ignored and the request is served from the cache, so no other site can spend the tracker's rate limit. POSTs (enqueue a request, create a job from free text, start or stop the daemon, answer a session's permission prompt, switch a session's permission mode, change a setting, set a job's effort, decide a job's repo proposals, merge a job's PR now with the job id typed back, raise or acknowledge a job's budget, acknowledge the repo budget, act on the Shelved list, set or clear focus, start a job's dev server, start, stop or restart a job's dev server or backing services, open a job's worktree in an editor, register a project: `/api/requests`, `/api/jobs`, `/api/daemon`, `/api/daemon/permission`, `/api/daemon/mode`, `/api/config`, `/api/jobs/:id/effort`, `/api/jobs/:id/repos`, `/api/jobs/:id/merge`, `/api/jobs/:id/budget`, `/api/budget/ack`, `/api/shelf`, `/api/focus`, `/api/jobs/:id/run`, `/api/jobs/:id/environment`, `/api/jobs/:id/editor`, the machine's `/api/projects`, and the chat routes `/api/chats`, `/api/chats/:id/rename`, `/api/chats/:id/archive` and `/api/chats/:id/messages`) need a random per-process token embedded in the served page, a matching Origin and a JSON content type, so other sites in your browser can't trigger work. After those three checks, a `Content-Length` over 64 KiB is a 413 `body too large` before the handler runs or anything is written. A body is counted in bytes as it arrives and decoded once at the end; one that passes 64 KiB, or is still incomplete after 10 s, is cut off (the request is destroyed, so the client sees the connection close) and answered 400, so a client with the token can't hold the server with an endless, oversized or trickled body. Every token comparison, header or query parameter, is constant-time. The guards live in `lib/server/http.ts`, and the route tables in `lib/server/start.ts` name each route's guards: dispatch runs the POST guard on every POST route, before its own guards, the project lookup and its handler. A `resume` for a job whose lease another driver holds live is refused with 409 naming the session, whatever its `args`, and nothing is queued, unless the driver is any id the job's own pool session has had and that session's child runs (asked of the pool session whose scope is that job, never `ps`), which the resume reaches and which reclaims as itself (`ownerStatus.jobSession`). A session that writes another pool session's id as its job's driver gains nothing: only the facts of the job's own session count, and that session's claim decides inside the job lock. The check runs after the token, Origin and JSON guards and only for a syntactically valid id with a `job.json`; it is advisory, because the job session's own claim inside the job lock still decides. A `resume`, `approve`, `revise-spec`, `rework` or `answer` for a shelved job is refused with 409 and nothing is queued (a `cancel` still goes): only a person takes a job off the shelf. `POST /api/shelf` is the dashboard's half of the human channel for `forge job unshelve` ([Daemon security](daemon-security.md) › Human-only operations): its body names the action and 1 to 50 `{id, shelvedAt}` entries, and each entry is pinned to the `shelved.at` the Shelved list showed, so a stale or replayed click is skipped (`shelved again since the list loaded`) rather than acting on a job shelved since. Anything but that exact shape is a 400 and writes nothing. Its `unshelved` events carry the `dashboard` actor, and a batch approve or rework covers only the parks its own gate card would send (never a budget, human check, input, issue link, infra or external wait). Focus is a pointer in `.forge/runtime/focus.json`, read through one non-blocking `O_NOFOLLOW` descriptor with a 64 KiB cap and honoured only for a valid job id with a `job.json`, so a planted symlink, FIFO or forged record reads as no focus; setting it starts, stops and signals no background process, and only starts the focused job's own backing services (ensure up, docs/CONFIG.md "Backing services"), whose names come from the validated id and config. Moving it may run the configured `checkout` steps (docs/CONFIG.md "Checkout steps"), which run configured commands and write symlinks at the configured fixed paths, linking only to a source whose realpath stays inside the job's own `<worktrees.root>/<id>` and running a command (or its undo) only when that job has its own contained worktree, as Run does; containment is checked when focus moves, not continuously, so a link's source swapped for a symlink out of the worktree afterwards is followed until the next switch; their record, `.forge/runtime/checkout.json`, is read the same no-follow way and only steers undo for targets and command pairs the current config names, so a POST to `/api/focus` (behind the same token, Origin and JSON guard) runs nothing the main checkout's config does not. `POST /api/jobs/:id/run` accepts only `{"command": "dev"}` and runs the configured `commands.dev` through `startBackground`, which reuses a live server rather than starting a second. `POST /api/jobs/:id/editor` runs `FORGE_EDITOR` (the human's own environment, trusted like `$EDITOR`; default `code`) split into argv with no shell, plus one argument: the job's worktree, and only when the stored value is itself `<worktrees.root>/<id>` (as configured or resolved, so `<own worktree>/x/..` is refused) and its realpath is a directory equal to the realpath of `<worktrees.root>` joined with the job id, so another job's worktree, an arbitrary directory, a symlink out or a value starting with `-` is a 409 and nothing is spawned; Run takes the same containment check, since job.json's `worktree` is agent-writable. The Environment card's routes treat the job dir (which the job's agents can write: `runtime.json`, `job.json`'s `worktree`, `logs/`) as hostile. `POST /api/jobs/:id/environment` takes only `{"target": "dev"|"backing", "action": "start"|"stop"|"restart"}` (400 otherwise); every action needs the job's own contained worktree as Run does, and start and restart an active job, else 409 with nothing spawned or signalled. Stop signals the dev server only after `ownDevProcess` proves the pid in `runtime.json` is the one Forge started for this job: an integer above 1 that is not the server's own, leading its own process group (and not the server's) with no controlling terminal (a shell the human opened in the worktree, and what it runs, keeps one), started within 30 s of the recorded `startedAt` (`ps -o pgid= -o tty= -o lstart=`), with its working directory inside the job's worktree (`/proc/<pid>/cwd` on Linux, `lsof -a -p <pid> -d cwd -Fn` on macOS; argv only). Anything unproven, and every pid on Windows, is a 409 that points at `forge stop`. A proven stop sends SIGTERM to the group, SIGKILL after 5 s, under the runtime lock, removes only the `dev` key and logs `background-stop` with `actor.source: dashboard`. Backing actions run `forge environment up <id>` (start) and `forge backing stop <id>` (stop, after which the server marks the job `stopped` in the environment record) as an async CLI child (`lib/engine/environment/status.ts` `forgeJson`, output capped, killed on timeout), because `lib/engine/environment/backing.ts` runs Docker synchronously and would freeze every request; `backing stop` stops only per-job containers whose labels name this checkout and job, keeping volumes, records and shared containers. `GET /api/jobs/:id/environment` and `GET /api/environments` need the token header, refuse a foreign Origin or a cross-site `Sec-Fetch-Site`, and are memoized (2 s per job, 5 s with one shared computation) because each read may spawn the CLI, `docker stats` and `ps`; container names reach `docker stats` only from the label-filtered listing and after a name regex. `GET /api/jobs/:id/environment/logs?source=dev|backing:<name>` takes the token as a constant-time-compared query parameter, as the transcript stream does, and counts toward the event-stream cap. The dev log is always `<jobDir>/logs/dev.log` (never `runtime.json`'s `log` field), confined to the real job dir and read through one non-blocking `O_NOFOLLOW` descriptor, so a symlink, FIFO or hard link is a 404; a container name is derived from config and the job id (the `<name>` must be a managed entry), checked against Docker's name charset, required to read `running` or `stopped` with this job's labels in `backing status` (else 409), and passed after `--` to `docker logs --follow --tail 200`, whose child is killed when the client leaves; a client that leaves while that status check runs gets no slot and no child, and a recycled container stream ends with `event: end` rather than reconnecting and replaying its last lines. Each line is sent as a JSON string, capped at 16 KiB, and rendered as text. The dev server runs unsandboxed, so Run (`startBackground`) opens that log with `openBackgroundLog` before it spawns anything: the `logs` dir must resolve to `<real root>/.forge/jobs/<id>/logs`, an existing log must be a regular file with a single link, and the log is opened `O_APPEND | O_CREAT | O_NOFOLLOW | O_NONBLOCK` and checked again through the descriptor. A planted symlink, `logs` dir link, FIFO or hard link is a ForgeError naming the file (409 from Run): nothing is spawned or written, and the link's target is untouched. A log that has reached `retention.logMaxBytes` (when that is null, one past 20 MiB, the session-log default) is first renamed to `dev.log.1`, replacing the older generation, so the log never grows without bound across starts. `POST /api/jobs/:id/repos` records `actor.source: dashboard` and decides only the `repos` the drawer listed: it is a 409, and nothing is written, unless they are exactly the pending set computed from the job's events, so a repo hidden from the session-editable `repo-proposals.json`, or proposed after the drawer loaded, is never approved unseen; it is also a 409 when nothing is pending or a clone check fails. The per-job `endpoints` in `/api/state` are derived from job state and config alone, and their `live` flag reads `runtime.json` through the same no-follow reader and signals 0, so polling opens no socket and spawns nothing. **Chats.** A chat's routes match only a 12-lowercase-hex id (`/api/chats/([0-9a-f]{12})…`), so any other id is a 404 before a handler runs, and the store checks it again before building a path. `GET /api/chats` lists them behind the read guard; `GET /api/chats/:id` (the chat and its session's state, redacted like a state frame) and `GET /api/chats/:id/log?after=N&limit=M` (a page of `log.jsonl`, every owner text and session line redacted with the scope's known values; a bad `after` or `limit` is a 400) also need the token, because they carry the owner's words. The chat session's own lines are also served by `/api/events` and `/api/daemons/log` under the read guard alone, like every other session's, so the token guards the owner's text, not the session's output. `POST /api/chats/:id/messages {text}` checks, in order and before appending anything, a text of 1 to 8000 characters (400), the chat (404), its state (409 for an archived chat), the pool (409 `start the daemon first`), its session (409 while it is busy or stopping) and the log's room (409 once it nears 64 MiB); then it appends the owner entry and hands the text to the pool's `sendChat`, the only path to a session's stdin that takes free text, and only for that chat's scope ([Daemon security](daemon-security.md) › Chats). A refused hand-off appends an `undelivered` entry and answers 409 with the pool's error. Titles go through `oneLineTitle` and are cut to 120 characters. Archiving a chat stops and drops its session. `/api/events`, `/api/daemons/log`, `/api/daemon/permission`, `/api/daemon/mode` and `/api/daemon` take a chat's `_chat-<id>` scope as they take any other (a chat with no `chat.json` is a 404 for the last two), and a scoped start of a chat answers 409: only a message starts one.

`GET /api/doctor` runs `git` and `gh`, so it also needs the token, and any Origin it sends must be ours. `GET /api/github/preview?url=` (the hover card on GitHub links) runs `gh api graphql` on the user's login and rate limit, so it takes the same token and Origin check; it answers only an `https://github.com/` repository, pull request, issue or commit URL, parsed into an owner, a name and a number or hex sha before `gh` is called with no shell, caches answers per page, and returns GitHub text that the card renders as text. The card also describes PR chips, whose URL passes `safeUrl` and opens with `noopener noreferrer`. `GET /api/config` (the settings schema and effective values), `GET /api/project` (the config-derived component graph only: names, repos, kinds, paths and edges, never commands, owners or notes) and `GET /api/about` (versions) only read: its commit, which can take `git` to find, is computed once when the server starts, never per request. `GET /api/jobs/:id` rejects a foreign Origin or a cross-site `Sec-Fetch-Site`, as the log routes do. `POST /api/config` goes through the same `setConfigValue` as `forge config set`: only the keys `lib/core/config/fields.ts` marks editable can be written, and none of them can name a command, file, module, tool or repository Forge runs or writes to, or loosen a security or attribution policy, so a forged or mistaken POST can't turn into code execution. `POST /api/jobs/:id/merge` is the dashboard's channel for a human-only operation (docs/architecture/daemon-security.md › Human-only operations): it takes exactly `{"now": true, "confirm": "<the job id>"}` (400 otherwise, with nothing called; 404 for an unknown job), merges as `forge pr merge --now` does, never past the merge order or a release gate, records `actor.source: dashboard`, and answers a refusal (no PR, a closed PR) with 409. `POST /api/budget/ack {period}` accepts only the current UTC month or day (400 otherwise, 409 when that period is within its cap), records `actor.source: dashboard`, and is not blocked while the daemon is wanted, because it writes the audit log, never `config.yml`. `POST /api/config` is refused with 409 while the daemon is wanted, because any change to `config.yml` would stop the daemon through its trust check, and the server never re-blesses that snapshot: only a human's Start does. The `/api/events` stream follows the same loopback Host rule and also rejects a mismatched Origin. Everything the page renders goes through Svelte's escaping interpolation; raw HTML is limited to the escape-first markdown renderer, `md()` (a test enforces the allowlist), so agent- and issue-authored markdown is escaped first, and inline markdown is tokenised into code, link, bare-URL and text segments that are each rendered once, so no autolink, emphasis or chip pass ever runs over generated HTML, and session log lines (headless session output) are parsed: tool input, tool results, supervisor and other lines render as plain text, while assistant and thinking prose, subagent prompts and reports, and the Thread's request text and replies render only through the escape-first `md()` (each surface has a Raw view of the exact text, and items over 20,000 characters stay text), and a session's stream is opened only while its job panel's Log tab (or the Inbox session log in the status bar's Inbox popover, or the office or assistant foreman log chosen in the Foreman popover) is shown and the tab is visible. `GET /api/jobs/:id/transcript` (a page of a job agent's, or an interactive owner's, Claude Code transcript, read backwards) and `GET /api/jobs/:id/transcript/events` (its live tail) are GET only and loopback only, refuse a foreign Origin or a cross-site `Sec-Fetch-Site`, and need the token: as the `x-forge-token` header for the page, and as a `token` query parameter (compared in constant time) for the stream, because EventSource can't send headers; the token reaches that URL only on our own same-origin page, which already embeds it. No query value is ever a path or a path segment: `agent` must be an own key of the job's `agents`, and every path is derived from job state, a session id that must be a UUID and an agent id that must match `^[A-Za-z0-9_-]{1,100}$`. Only this repo's project dirs are tried (the slugs of the root, its realpath and the job's worktree under `$CLAUDE_CONFIG_DIR/projects`, else `~/.claude/projects`), never another repo's: the worktree counts only when it is the job's own (`<worktrees.root>/<id>`) or sits under the worktrees dir, as written and resolved, since job.json is agent-writable. A project dir must resolve to exactly `<projects>/<slug>` and the transcript's realpath must stay inside that slug dir (checked at lookup and again when the file is opened, not merely anywhere under the projects dir), and the file is then checked to be a regular file and read through one non-blocking `O_NOFOLLOW` descriptor (held open for the stream's life, so a symlink swapped in later can't redirect it), so a planted symlink or FIFO is a 404. The owner route answers only for an owner in no daemon session record. The stream counts toward the event-stream cap, is recycled like the others, never receives the pool's frames and stops polling the file when it closes. `/api/state` carries each running agent's last tool call or line of text from the last 64 KiB of its transcript, cached by size and mtime. Transcript text is returned as data inside JSON and SSE frames and rendered as text, or through `md()` for prose, like the session log. The page itself (`/` and `/index.html`) is served with `Content-Security-Policy: frame-src 'self'; frame-ancestors 'none'` and `X-DNS-Prefetch-Control: off`. No other site can frame it, which closes clickjacking: a framed page's own scripts would send token-bearing POSTs for whatever a disguised click hit. The page frames only its own origin. The page CSP stops at those two directives, so the inline theme script needs no hash. Job HTML (mockups) is shown in an iframe with `sandbox=""`, no allow tokens, and `/raw` serves it with `Content-Security-Policy: sandbox; default-src 'none'; style-src 'unsafe-inline'; img-src data:; font-src data:; frame-ancestors 'self'` and `X-DNS-Prefetch-Control: off`. A mockup runs no script at all, so it can't set `location`, open an `RTCPeerConnection` or prefetch through script. The sandbox also blocks `<meta http-equiv="refresh">`, popups, forms and top navigation, and the CSP blocks every subresource load and every connection, so a mockup must be self-contained (inline CSS, `data:` images and fonts) and secrets a misled agent wrote into it aren't sent off the machine when a human opens it. A clicked link can still navigate the frame itself, and the page's `frame-src 'self'` blocks any other origin there. `/raw` takes `frame-ancestors 'self'` rather than `'none'` because the dashboard's own Files tab frames it. CSS still renders, so state toggles use CSS (`:target`, `<details>`), as the designer prompt says. What stays residual: DNS-prefetch hints in a mockup's markup where a browser ignores `X-DNS-Prefetch-Control`, and a user who copies a URL out of a mockup. `GET /api/jobs/:id/file` and `/raw` take a valid job id and a lexically joined path, refuse private job files by name (or by the name a link resolves to), and open every file through `openConfinedLog`: the job dir itself must resolve to `<real root>/.forge/jobs/<id>`, the file must resolve inside it, and it must be a regular file with a single link, read through the one non-blocking `O_NOFOLLOW` descriptor that check opened and re-checked after the open (realpath and inode). A file or directory symlink out, a symlinked job dir, a FIFO, a device or a hard link (to an outside file or a private one) is a 404, and none of them blocks the server. The open runs on Node, which has no `openat`, so a parent directory swapped for a symlink and back within microseconds of the open stays a recorded residual. `/raw` serves only `.html` files (a log or JSON file served as `text/html` would run as a page) and refuses one over 2 MiB with 413 `file too large`; `/file` serves the last 2 MiB of a larger text file. Screenshot images are served only from a job's `screenshots/` dir, only as PNG/JPEG/WebP (never SVG or other active types), with `nosniff`, a `default-src 'none'` CSP, `Cross-Origin-Resource-Policy: same-origin` (so another site can't embed them, even though its `<img>` would carry a loopback Host), a 10 MiB cap, and the same `openConfinedLog` open as other job files. The page loads no external scripts, styles or fonts: Tailwind is compiled into the committed `dashboard/dist/`, the three typefaces are vendored woff2 files (`dashboard/fonts/`, OFL) served from the same origin, and the film grain is an inline SVG `data:` URI. The server serves only the page (`no-store`, token injected) and the hashed `assets/*.js|css|woff2` files that `dist/manifest.json` lists (never SVG or HTML), matched by exact path and cached immutably. Nothing is served by directory, so the sources, the manifest and the rest of the plugin root never are.

`GET /api/doctor/bundle` (Settings › Diagnostics › Download support bundle) returns the redacted support bundle (docs/CLI.md "Support bundle") as a zip. It takes the token in the `x-forge-token` header only, never as a query parameter, so it can't leak through a URL; an Origin, when sent, must be ours and a cross-site `Sec-Fetch-Site` is refused, so another site can neither read it nor trigger the git and gh work behind it. The optional `job` is checked with `validJobId` before any path is built, every other parameter is ignored (the endpoint never includes agent text or diffs), and the reply is `no-store`, `nosniff` and `Cross-Origin-Resource-Policy: same-origin`. Every file it reads comes from inside the job dir or the runtime dir, both checked to resolve where they should, and is opened with `O_NOFOLLOW | O_NONBLOCK` and read through that same descriptor, so a planted symlink or FIFO is skipped rather than followed or waited on.

`forge dash --dev` (what `npm run dev` runs) changes only where the page and assets come from: the fixed `node_modules/.cache/forge/dashboard-dev/` inside the plugin root, which is exactly as trusted as `dashboard/dist/` (anyone who can write either can already rewrite `lib/server/`). It takes no path, so it can't serve a job worktree's files. The loopback Host, token, Origin and JSON-POST guards and the manifest allowlist are the same in dev mode. The flag is CLI-only: no config key and no `/api` route sets it. A dev dashboard never starts the daemon by itself (only Start does), so a fresh clone of a repo that commits `daemon.enabled: true` doesn't boot a paid session; it serves every project of `FORGE_HOME` with no pool booting, and it refuses to start while a proven machine dashboard runs instead of taking it over.

`GET /api/mandates/:id/draft` (the read guard) and `POST /api/mandates/:id/draft` (the token, Origin and JSON guard) serve a goal mandate's milestone draft and decide it (docs/architecture/foreman.md "Milestone approval and filing"). Both check the id with `isMandateId` before any path is built. The POST body is exactly `{decision: approve | revise | reject, request, digest, note?}`, with `digest` 64 lowercase hex; any other shape is a 400 with nothing read. It calls the CLI's `decideDraft` as a person (`actor.source: dashboard`), pinned to the request and digest of the GET the card rendered, so a draft that changed since is a 409 and nothing is decided unseen; every other refusal (a missing note on revise, a likely secret, a decision already running, a tracker failure) is a 409 too. Filing runs in the handler, as the tracker contract is synchronous. The card renders every draft, goal, title and error string as Svelte text; the only `{@html}` is `md()` over an issue's why, what to do and done.
