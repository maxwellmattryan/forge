# Dashboard security

The server binds 127.0.0.1 only and answers only requests whose Host is a loopback name, which defeats DNS rebinding. GETs are read-only. POSTs (enqueue a request, create a job from free text, start or stop the daemon, answer a session's permission prompt, switch a session's permission mode, change a setting, set a job's effort, decide a job's repo proposals, acknowledge the repo budget, set or clear focus, start a job's dev server, start, stop or restart a job's dev server or backing services, open a job's worktree in an editor: `/api/requests`, `/api/jobs`, `/api/daemon`, `/api/daemon/permission`, `/api/daemon/mode`, `/api/config`, `/api/jobs/:id/effort`, `/api/jobs/:id/repos`, `/api/budget/ack`, `/api/focus`, `/api/jobs/:id/run`, `/api/jobs/:id/environment`, `/api/jobs/:id/editor`) need a random per-process token embedded in the served page, a matching Origin and a JSON content type, so other sites in your browser can't trigger work. The guards live in `lib/server/http.ts`, and the route table in `lib/server/start.ts` names each route's guards: dispatch runs the POST guard on every POST route, before its own guards and its handler. A `resume` for a job whose lease another driver holds live is refused with 409 naming the session, whatever its `args`, and nothing is queued, unless the driver is any id the job's own pool session has had and that session's child runs (asked of the pool session whose scope is that job, never `ps`), which the resume reaches and which reclaims as itself (`ownerStatus.jobSession`). A session that writes another pool session's id as its job's driver gains nothing: only the facts of the job's own session count, and that session's claim decides inside the job lock. The check runs after the token, Origin and JSON guards and only for a syntactically valid id with a `job.json`; it is advisory, because the job session's own claim inside the job lock still decides. Focus is a pointer in `.forge/runtime/focus.json`, read through one non-blocking `O_NOFOLLOW` descriptor with a 64 KiB cap and honoured only for a valid job id with a `job.json`, so a planted symlink, FIFO or forged record reads as no focus; setting it starts, stops and signals no background process, and only starts the focused job's own backing services (ensure up, docs/CONFIG.md "Backing services"), whose names come from the validated id and config. Moving it may run the configured `checkout` steps (docs/CONFIG.md "Checkout steps"), which run configured commands and write symlinks at the configured fixed paths, linking only to a source whose realpath stays inside the job's own `<worktrees.root>/<id>` and running a command (or its undo) only when that job has its own contained worktree, as Run does; containment is checked when focus moves, not continuously, so a link's source swapped for a symlink out of the worktree afterwards is followed until the next switch; their record, `.forge/runtime/checkout.json`, is read the same no-follow way and only steers undo for targets and command pairs the current config names, so a POST to `/api/focus` (behind the same token, Origin and JSON guard) runs nothing the main checkout's config does not. `POST /api/jobs/:id/run` accepts only `{"command": "dev"}` and runs the configured `commands.dev` through `startBackground`, which reuses a live server rather than starting a second. `POST /api/jobs/:id/editor` runs `FORGE_EDITOR` (the human's own environment, trusted like `$EDITOR`; default `code`) split into argv with no shell, plus one argument: the job's worktree, and only when the stored value is itself `<worktrees.root>/<id>` (as configured or resolved, so `<own worktree>/x/..` is refused) and its realpath is a directory equal to the realpath of `<worktrees.root>` joined with the job id, so another job's worktree, an arbitrary directory, a symlink out or a value starting with `-` is a 409 and nothing is spawned; Run takes the same containment check, since job.json's `worktree` is agent-writable. The Environment card's routes treat the job dir (which the job's agents can write: `runtime.json`, `job.json`'s `worktree`, `logs/`) as hostile. `POST /api/jobs/:id/environment` takes only `{"target": "dev"|"backing", "action": "start"|"stop"|"restart"}` (400 otherwise); every action needs the job's own contained worktree as Run does, and start and restart an active job, else 409 with nothing spawned or signalled. Stop signals the dev server only after `ownDevProcess` proves the pid in `runtime.json` is the one Forge started for this job: an integer above 1 that is not the server's own, leading its own process group (and not the server's) with no controlling terminal (a shell the human opened in the worktree, and what it runs, keeps one), started within 30 s of the recorded `startedAt` (`ps -o pgid= -o tty= -o lstart=`), with its working directory inside the job's worktree (`/proc/<pid>/cwd` on Linux, `lsof -a -p <pid> -d cwd -Fn` on macOS; argv only). Anything unproven, and every pid on Windows, is a 409 that points at `forge stop`. A proven stop sends SIGTERM to the group, SIGKILL after 5 s, under the runtime lock, removes only the `dev` key and logs `background-stop` with `actor.source: dashboard`. Backing actions run `forge environment up <id>` (start) and `forge backing stop <id>` (stop, after which the server marks the job `stopped` in the environment record) as an async CLI child (`lib/engine/environment/status.ts` `forgeJson`, output capped, killed on timeout), because `lib/engine/environment/backing.ts` runs Docker synchronously and would freeze every request; `backing stop` stops only per-job containers whose labels name this checkout and job, keeping volumes, records and shared containers. `GET /api/jobs/:id/environment` and `GET /api/environments` need the token header, refuse a foreign Origin or a cross-site `Sec-Fetch-Site`, and are memoized (2 s per job, 5 s with one shared computation) because each read may spawn the CLI, `docker stats` and `ps`; container names reach `docker stats` only from the label-filtered listing and after a name regex. `GET /api/jobs/:id/environment/logs?source=dev|backing:<name>` takes the token as a constant-time-compared query parameter, as the transcript stream does, and counts toward the event-stream cap. The dev log is always `<jobDir>/logs/dev.log` (never `runtime.json`'s `log` field), confined to the real job dir and read through one non-blocking `O_NOFOLLOW` descriptor, so a symlink or FIFO is a 404; a container name is derived from config and the job id (the `<name>` must be a managed entry), checked against Docker's name charset, required to read `running` or `stopped` with this job's labels in `backing status` (else 409), and passed after `--` to `docker logs --follow --tail 200`, whose child is killed when the client leaves; a client that leaves while that status check runs gets no slot and no child, and a recycled container stream ends with `event: end` rather than reconnecting and replaying its last lines. Each line is sent as a JSON string, capped at 16 KiB, and rendered as text. `POST /api/jobs/:id/repos` records `actor.source: dashboard` and decides only the `repos` the drawer listed: it is a 409, and nothing is written, unless they are exactly the pending set computed from the job's events, so a repo hidden from the session-editable `repo-proposals.json`, or proposed after the drawer loaded, is never approved unseen; it is also a 409 when nothing is pending or a clone check fails. The per-job `endpoints` in `/api/state` are derived from job state and config alone, and their `live` flag reads `runtime.json` through the same no-follow reader and signals 0, so polling opens no socket and spawns nothing. `GET /api/doctor` runs `git` and `gh`, so it also needs the token, and any Origin it sends must be ours. `GET /api/github/preview?url=` (the hover card on GitHub links) runs `gh api graphql` on the user's login and rate limit, so it takes the same token and Origin check; it answers only an `https://github.com/` repository, pull request, issue or commit URL, parsed into an owner, a name and a number or hex sha before `gh` is called with no shell, caches answers per page, and returns GitHub text that the card renders as text. The card also describes PR chips, whose URL passes `safeUrl` and opens with `noopener noreferrer`. `GET /api/config` (the settings schema and effective values), `GET /api/project` (the config-derived component graph only: names, repos, kinds, paths and edges, never commands, owners or notes) and `GET /api/about` (versions) only read: its commit, which can take `git` to find, is computed once when the server starts, never per request. `GET /api/jobs/:id` rejects a foreign Origin or a cross-site `Sec-Fetch-Site`, as the log routes do. `POST /api/config` goes through the same `setConfigValue` as `forge config set`: only the keys `lib/core/config/fields.ts` marks editable can be written, and none of them can name a command, file, module, tool or repository Forge runs or writes to, or loosen a security or attribution policy, so a forged or mistaken POST can't turn into code execution. `POST /api/budget/ack {period}` accepts only the current UTC month or day (400 otherwise, 409 when that period is within its cap), records `actor.source: dashboard`, and is not blocked while the daemon is wanted, because it writes the audit log, never `config.yml`. `POST /api/config` is refused with 409 while the daemon is wanted, because any change to `config.yml` would stop the daemon through its trust check, and the server never re-blesses that snapshot: only a human's Start does. The `/api/events` stream follows the same loopback Host rule and also rejects a mismatched Origin. Everything the page renders goes through Svelte's escaping interpolation; raw HTML is limited to the escape-first markdown renderer, `md()` (a test enforces the allowlist), so agent- and issue-authored markdown is escaped first, and inline markdown is tokenised into code, link, bare-URL and text segments that are each rendered once, so no autolink, emphasis or chip pass ever runs over generated HTML, and session log lines (headless session output) are parsed: tool input, tool results, supervisor and other lines render as plain text, while assistant and thinking prose, subagent prompts and reports, and the Thread's request text and replies render only through the escape-first `md()` (each surface has a Raw view of the exact text, and items over 20,000 characters stay text), and a session's stream is opened only while its job panel's Log tab (or the Inbox session log in the status bar's Daemon popover, or the office log in the Foreman popover) is shown and the tab is visible. `GET /api/jobs/:id/transcript` (a page of a job agent's, or an interactive owner's, Claude Code transcript, read backwards) and `GET /api/jobs/:id/transcript/events` (its live tail) are GET only and loopback only, refuse a foreign Origin or a cross-site `Sec-Fetch-Site`, and need the token: as the `x-forge-token` header for the page, and as a `token` query parameter (compared in constant time) for the stream, because EventSource can't send headers; the token reaches that URL only on our own same-origin page, which already embeds it. No query value is ever a path or a path segment: `agent` must be an own key of the job's `agents`, and every path is derived from job state, a session id that must be a UUID and an agent id that must match `^[A-Za-z0-9_-]{1,100}$`. Only this repo's project dirs are tried (the slugs of the root, its realpath and the job's worktree under `$CLAUDE_CONFIG_DIR/projects`, else `~/.claude/projects`), never another repo's: the worktree counts only when it is the job's own (`<worktrees.root>/<id>`) or sits under the worktrees dir, as written and resolved, since job.json is agent-writable. A project dir must resolve to exactly `<projects>/<slug>` and the transcript's realpath must stay inside that slug dir (checked at lookup and again when the file is opened, not merely anywhere under the projects dir), and the file is then checked to be a regular file and read through one non-blocking `O_NOFOLLOW` descriptor (held open for the stream's life, so a symlink swapped in later can't redirect it), so a planted symlink or FIFO is a 404. The owner route answers only for an owner in no daemon session record. The stream counts toward the event-stream cap, is recycled like the others, never receives the pool's frames and stops polling the file when it closes. `/api/state` carries each running agent's last tool call or line of text from the last 64 KiB of its transcript, cached by size and mtime. Transcript text is returned as data inside JSON and SSE frames and rendered as text, or through `md()` for prose, like the session log. Job HTML (mockups) is shown in a sandboxed iframe and served with `Content-Security-Policy: sandbox allow-scripts; default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data:; font-src data:`, so a mockup must be self-contained: it blocks every subresource load (external scripts, styles, images, fonts, media, frames, workers) and every connection (`fetch`, XHR, WebSocket, EventSource), so secrets a misled agent wrote into a mockup aren't sent off the machine when a human opens it. CSP has no working directive for the rest, which stays residual risk: the frame navigating itself (`location = …`), a user clicking a link, WebRTC and DNS prefetch. File reads are confined to the job directory. Screenshot images are served only from a job's `screenshots/` dir, only as PNG/JPEG/WebP (never SVG or other active types), with `nosniff`, a `default-src 'none'` CSP, `Cross-Origin-Resource-Policy: same-origin` (so another site can't embed them, even though its `<img>` would carry a loopback Host), a 10 MiB cap, and a realpath check that keeps symlinks from escaping the job dir; the file is then checked and read through one descriptor. The page loads no external scripts, styles or fonts: Tailwind is compiled into the committed `dashboard/dist/`, the three typefaces are vendored woff2 files (`dashboard/fonts/`, OFL) served from the same origin, and the film grain is an inline SVG `data:` URI. The server serves only the page (`no-store`, token injected) and the hashed `assets/*.js|css|woff2` files that `dist/manifest.json` lists (never SVG or HTML), matched by exact path and cached immutably. Nothing is served by directory, so the sources, the manifest and the rest of the plugin root never are.

`GET /api/doctor/bundle` (Settings › Diagnostics › Download support bundle) returns the redacted support bundle (docs/CLI.md "Support bundle") as a zip. It takes the token in the `x-forge-token` header only, never as a query parameter, so it can't leak through a URL; an Origin, when sent, must be ours and a cross-site `Sec-Fetch-Site` is refused, so another site can neither read it nor trigger the git and gh work behind it. The optional `job` is checked with `validJobId` before any path is built, every other parameter is ignored (the endpoint never includes agent text or diffs), and the reply is `no-store`, `nosniff` and `Cross-Origin-Resource-Policy: same-origin`. Every file it reads comes from inside the job dir or the runtime dir, both checked to resolve where they should, and is opened with `O_NOFOLLOW | O_NONBLOCK` and read through that same descriptor, so a planted symlink or FIFO is skipped rather than followed or waited on.

`forge dash --dev` (what `npm run dev` runs) changes only where the page and assets come from: the fixed `node_modules/.cache/forge/dashboard-dev/` inside the plugin root, which is exactly as trusted as `dashboard/dist/` (anyone who can write either can already rewrite `lib/server/`). It takes no path, so it can't serve a job worktree's files. The loopback Host, token, Origin and JSON-POST guards and the manifest allowlist are the same in dev mode. The flag is CLI-only: no config key and no `/api` route sets it. A dev dashboard never starts the daemon by itself (only Start does), so a fresh clone of a repo that commits `daemon.enabled: true` doesn't boot a paid session, and it refuses to start beside a live dashboard for the same repo instead of taking it over.
