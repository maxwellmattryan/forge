# Dashboard security › POST routes

Part of [Dashboard security](../dashboard-security.md).

## Resume and the lease
A `resume` for a job whose lease another driver holds live is refused with 409 naming the session, whatever its `args`, and nothing is queued, unless the driver is any id the job's own pool session has had and that session's child runs (asked of the pool session whose scope is that job, never `ps`), which the resume reaches and which reclaims as itself (`ownerStatus.jobSession`). A session that writes another pool session's id as its job's driver gains nothing: only the facts of the job's own session count, and that session's claim decides inside the job lock. The check runs after the login, Origin and JSON guards and only for a syntactically valid id with a `job.json`; it is advisory, because the job session's own claim inside the job lock still decides.

## Shelved jobs
A `resume`, `approve`, `revise-spec`, `rework` or `answer` for a shelved job is refused with 409 and nothing is queued (a `cancel` still goes): only a person takes a job off the shelf.

`POST /api/shelf` is the dashboard's half of the human channel for `forge job unshelve` ([Daemon security › Human-only operations](../daemon-security/human-only-operations.md)): its body names the action and 1 to 50 `{id, shelvedAt}` entries, and each entry is pinned to the `shelved.at` the Shelved list showed, so a stale or replayed click is skipped (`shelved again since the list loaded`) rather than acting on a job shelved since. Anything but that exact shape is a 400 and writes nothing. Its `unshelved` events carry the `dashboard` actor, and a batch approve or rework covers only the parks its own gate card would send (never a budget, human check, input, issue link, infra or external wait).

## Focus and checkout steps
Focus is a pointer in `.forge/runtime/focus.json`, read through one non-blocking `O_NOFOLLOW` descriptor with a 64 KiB cap and honoured only for a valid job id with a `job.json`, so a planted symlink, FIFO or forged record reads as no focus; setting it starts, stops and signals no background process, and only starts the focused job's own backing services (ensure up, docs/CONFIG.md "Backing services"), whose names come from the validated id and config.

Moving it may run the configured `checkout` steps (docs/CONFIG.md "Checkout steps"), which run configured commands and write symlinks at the configured fixed paths, linking only to a source whose realpath stays inside the job's own `<worktrees.root>/<id>` and running a command (or its undo) only when that job has its own contained worktree, as Run does; containment is checked when focus moves, not continuously, so a link's source swapped for a symlink out of the worktree afterwards is followed until the next switch; their record, `.forge/runtime/checkout.json`, is read the same no-follow way and only steers undo for targets and command pairs the current config names, so a POST to `/api/focus` (behind the same login, Origin and JSON guard) runs nothing the main checkout's config does not.

## Run and the editor
`POST /api/jobs/:id/run` accepts only `{"command": "dev"}` and runs the configured `commands.dev` through `startBackground`, which reuses a live server rather than starting a second.

`POST /api/jobs/:id/editor` runs `FORGE_EDITOR` (the human's own environment, trusted like `$EDITOR`; default `code`) split into argv with no shell, plus one argument: the job's worktree, and only when the stored value is itself `<worktrees.root>/<id>` (as configured or resolved, so `<own worktree>/x/..` is refused) and its realpath is a directory equal to the realpath of `<worktrees.root>` joined with the job id, so another job's worktree, an arbitrary directory, a symlink out or a value starting with `-` is a 409 and nothing is spawned; Run takes the same containment check, since job.json's `worktree` is agent-writable.

## The Environment card
The Environment card's routes treat the job dir (which the job's agents can write: `runtime.json`, `job.json`'s `worktree`, `logs/`) as hostile. `POST /api/jobs/:id/environment` takes only `{"target": "dev"|"backing", "action": "start"|"stop"|"restart"}` (400 otherwise); every action needs the job's own contained worktree as Run does, and start and restart an active job, else 409 with nothing spawned or signalled.

Stop signals the dev server only after `ownDevProcess` proves the pid in `runtime.json` is the one Forge started for this job: an integer above 1 that is not the server's own, leading its own process group (and not the server's) with no controlling terminal (a shell the human opened in the worktree, and what it runs, keeps one), started within 30 s of the recorded `startedAt` (`ps -o pgid= -o tty= -o lstart=`), with its working directory inside the job's worktree (`/proc/<pid>/cwd` on Linux, `lsof -a -p <pid> -d cwd -Fn` on macOS; argv only). Anything unproven, and every pid on Windows, is a 409 that points at `forge stop`. A proven stop sends SIGTERM to the group, SIGKILL after 5 s, under the runtime lock, removes only the `dev` key and logs `background-stop` with `actor.source: dashboard`.

Backing actions run `forge environment up <id>` (start) and `forge backing stop <id>` (stop, after which the server marks the job `stopped` in the environment record) as an async CLI child (`lib/engine/environment/status.ts` `forgeJson`, output capped, killed on timeout), because `lib/engine/environment/backing.ts` runs Docker synchronously and would freeze every request; `backing stop` stops only per-job containers whose labels name this checkout and job, keeping volumes, records and shared containers.

`GET /api/jobs/:id/environment` and `GET /api/environments` need the login, refuse a foreign Origin or a cross-site `Sec-Fetch-Site`, and are memoized (2 s per job, 5 s with one shared computation) because each read may spawn the CLI, `docker stats` and `ps`; container names reach `docker stats` only from the label-filtered listing and after a name regex.

## Environment logs
`GET /api/jobs/:id/environment/logs?source=dev|backing:<name>` is an EventSource stream, which carries the login cookie on its own as the transcript stream does, and counts toward the event-stream cap. The dev log is always `<jobDir>/logs/dev.log` (never `runtime.json`'s `log` field), confined to the real job dir and read through one non-blocking `O_NOFOLLOW` descriptor, so a symlink, FIFO or hard link is a 404; a container name is derived from config and the job id (the `<name>` must be a managed entry), checked against Docker's name charset, required to read `running` or `stopped` with this job's labels in `backing status` (else 409), and passed after `--` to `docker logs --follow --tail 200`, whose child is killed when the client leaves; a client that leaves while that status check runs gets no slot and no child, and a recycled container stream ends with `event: end` rather than reconnecting and replaying its last lines. Each line is sent as a JSON string, capped at 16 KiB, and rendered as text.

The dev server runs unsandboxed, so Run (`startBackground`) opens that log with `openBackgroundLog` before it spawns anything: the `logs` dir must resolve to `<real root>/.forge/jobs/<id>/logs`, an existing log must be a regular file with a single link, and the log is opened `O_APPEND | O_CREAT | O_NOFOLLOW | O_NONBLOCK` and checked again through the descriptor. A planted symlink, `logs` dir link, FIFO or hard link is a ForgeError naming the file (409 from Run): nothing is spawned or written, and the link's target is untouched. A log that has reached `retention.logMaxBytes` (when that is null, one past 20 MiB, the session-log default) is first renamed to `dev.log.1`, replacing the older generation, so the log never grows without bound across starts.

## Repo proposals and endpoints
`POST /api/jobs/:id/repos` records `actor.source: dashboard` and decides only the `repos` the drawer listed: it is a 409, and nothing is written, unless they are exactly the pending set computed from the job's events, so a repo hidden from the session-editable `repo-proposals.json`, or proposed after the drawer loaded, is never approved unseen; it is also a 409 when nothing is pending or a clone check fails.

The per-job `endpoints` in `/api/state` are derived from job state and config alone, and their `live` flag reads `runtime.json` through the same no-follow reader and signals 0, so polling opens no socket and spawns nothing.

## Chats
**Chats.** A chat's routes match only a 12-lowercase-hex id (`/api/chats/([0-9a-f]{12})…`), so any other id is a 404 before a handler runs, and the store checks it again before building a path. `GET /api/chats` lists them behind the read guard; `GET /api/chats/:id` (the chat and its session's state, redacted like a state frame) and `GET /api/chats/:id/log?after=N&limit=M` (a page of `log.jsonl`, every owner text and session line redacted with the scope's known values; a bad `after` or `limit` is a 400) carry the owner's words, behind the login like every `/api` route. The chat session's own lines are also served by `/api/events` and `/api/daemons/log` under the same login and read guard, like every other session's.

`POST /api/chats/:id/messages {text}` checks, in order and before appending anything, a text of 1 to 8000 characters (400), the chat (404), its state (409 for an archived chat), the pool (409 `start the daemon first`), its session (409 while it is busy or stopping) and the log's room (409 once it nears 64 MiB); then it appends the owner entry and hands the text to the pool's `sendChat`, the only path to a session's stdin that takes free text, and only for that chat's scope ([Daemon security › Chats](../daemon-security/chats.md)). A refused hand-off appends an `undelivered` entry and answers 409 with the pool's error.

Titles go through `oneLineTitle` and are cut to 120 characters. Archiving a chat stops and drops its session. `/api/events`, `/api/daemons/log`, `/api/daemon/permission`, `/api/daemon/mode` and `/api/daemon` take a chat's `_chat-<id>` scope as they take any other (a chat with no `chat.json` is a 404 for the last two), and a scoped start of a chat answers 409: only a message starts one.
