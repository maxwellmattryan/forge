# Dashboard security › Projects

Part of [Dashboard security](../dashboard-security.md).

**One server, many projects.** The machine dashboard serves every project in the machine index from one server, with one token, one port and one runtime record. Project endpoints live under `/api/p/<project>/<x>` (the `/api/<x>` paths in this topic's parts are written relative to that prefix): `GET /api/state` and every other bare project path answer 404.
- Machine endpoints keep top-level paths: the page (`/`, `/index.html`), `/assets/*`, `/forge.png`, `GET /api/about`, `GET /api/projects` (the registered projects, their job counts, latest job and pools, and the machine cap), `GET /api/projects/events` (its SSE stream, a `projects` frame on connect and on change) and `GET /api/projects/stats?days=7|30|90` (each loaded project's shipped jobs and cost per UTC day, names and numbers only; any other `days` is 400, so a crafted query can't widen the ledger reads, and the ledger is read without writing), each `/api` one behind the login and the read guard.
- `POST /api/projects` (the dashboard's Add project, behind the login, Origin and JSON guard like every POST) registers a repo as `forge project add <path>` does: its body is exactly `{"path": string, "name"?: string}`, and a body with another key or a non-string value, a `path` that is empty, over 4096 characters, holds a NUL, CR or LF, or is neither absolute nor `~` / `~/…` (so never relative to the server's cwd or another user's `~bob`), or a non-empty `name` failing `PROJECT_NAME` is a 400 before any filesystem or git call.
- The path then resolves through `resolveProjectRoot` (`~` expanded, a worktree or subdirectory to its main checkout's realpath, `.forge/config.yml` required; git sees the path only as its `cwd`), and its refusals are a 400; a name another path holds, or a machine index this Forge can't read, is a 409 with the index untouched. The same repo again is `added: false` and writes nothing. It never approves the project's trusted files, so a project with `daemon.enabled: true` waits for a human's Start (docs/architecture/daemon-security.md).
- `lib/server/start.ts` holds two route tables, `ROUTES` (matched on the full path) and `PROJECT_ROUTES` (matched on the path after `/api/p/<project>`). Dispatch runs the loopback checks, matches a row, checks the login, runs the POST guard and the row's guards, and only then resolves the project segment: it must match `PROJECT_NAME` (`^[a-z0-9][a-z0-9._-]{0,63}$`) before anything reads the index, then name a loaded project, after one re-read of the index on a miss; anything else is `404 {"error":"no registered project \"<name>\""}` (the name cut to 64 characters, JSON-escaped). So a cross-site or signed-out request never reads the index, and `..`, `%2F`, uppercase or an overlong name never reaches another project.
- Job ids resolve only inside the project the path names: the same id in two projects is each project's own job, and `/file` and `/raw` confine to that project's job dir, so an absolute path, a `..` or a symlink into another project's files is refused like any outside path.
- Event streams are keyed `<project>/<scope>` in the machine's one client map, so a stream on one project's `_inbox` never gets another's frames, and `MAX_SSE_CLIENTS` (8) counts streams machine-wide, `/api/projects/events` included.
