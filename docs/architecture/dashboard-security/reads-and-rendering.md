# Dashboard security › Reads and rendering

Part of [Dashboard security](../dashboard-security.md).

## Doctor, GitHub and tracker reads
`GET /api/doctor` runs `git` and `gh` behind the login, and any Origin it sends must be ours. `GET /api/github/preview?url=` (the hover card on GitHub links) runs `gh api graphql` on the user's GitHub login and rate limit, behind the same login and Origin check; it answers only an `https://github.com/` repository, pull request, issue or commit URL, parsed into an owner, a name and a number or hex sha before `gh` is called with no shell, caches answers per page, and returns GitHub text that the card renders as text.

`GET /api/backlog/item?ref=` (the issue panel) runs the tracker, `gh issue view` for GitHub, behind the same login and Origin check; it refuses a ref that is empty, over 200 characters or holds a control character with 400, the GitHub adapter takes only this repo's issue number and passes it after `--`, and the issue text it returns is unfenced and display only: the panel renders the body and comments through `md()` and nothing else. The card also describes PR chips, whose URL passes `safeUrl` and opens with `noopener noreferrer`.

## Config, project and about reads
`GET /api/config` (the settings schema and effective values), `GET /api/project` (the config-derived component graph only: names, repos, kinds, paths and edges, never commands, owners or notes) and `GET /api/about` (versions) only read: its commit, which can take `git` to find, is computed once when the server starts, never per request. `GET /api/jobs/:id` rejects a foreign Origin or a cross-site `Sec-Fetch-Site`, as the log routes do.

## Settings, merge and budget writes
`POST /api/config` goes through the same `setConfigValue` as `forge config set`: only the keys `lib/core/config/fields.ts` marks editable can be written, and none of them can name a command, file, module, tool or repository Forge runs or writes to, or loosen a security or attribution policy, so a forged or mistaken POST can't turn into code execution.

`POST /api/jobs/:id/merge` is the dashboard's channel for a human-only operation (docs/architecture/daemon-security/human-only-operations.md): it takes exactly `{"now": true, "confirm": "<the job id>"}` (400 otherwise, with nothing called; 404 for an unknown job), merges as `forge pr merge --now` does, never past the merge order or a release gate, records `actor.source: dashboard`, and answers a refusal (no PR, a closed PR) with 409.

`POST /api/budget/ack {period}` accepts only the current UTC month or day (400 otherwise, 409 when that period is within its cap), records `actor.source: dashboard`, and is not blocked while the daemon is wanted, because it writes the audit log, never `config.yml`. `POST /api/config` is refused with 409 while the daemon is wanted, because any change to `config.yml` would stop the daemon through its trust check, and the server never re-blesses that snapshot: only a human's Start does. The `/api/events` stream follows the same loopback Host rule and also rejects a mismatched Origin.

## Escape-first rendering
Everything the page renders goes through Svelte's escaping interpolation; raw HTML is limited to the escape-first markdown renderer, `md()` (a test enforces the allowlist), so agent- and issue-authored markdown is escaped first, and inline markdown is tokenised into code, link, bare-URL and text segments that are each rendered once, so no autolink, emphasis or chip pass ever runs over generated HTML.

Session log lines (headless session output) are parsed: tool input, tool results, supervisor and other lines render as plain text, while assistant and thinking prose, subagent prompts and reports, and the Thread's request text and replies render only through the escape-first `md()` (each surface has a Raw view of the exact text, and items over 20,000 characters stay text), and a session's stream is opened only while its job panel's Log tab (or the Inbox session log in the status bar's Inbox popover) is shown and the tab is visible.

## Transcripts
`GET /api/jobs/:id/transcript` (a page of a job agent's, or an interactive owner's, Claude Code transcript, read backwards) and `GET /api/jobs/:id/transcript/events` (its live tail) are GET only and loopback only, refuse a foreign Origin or a cross-site `Sec-Fetch-Site`, and need the login: the page's fetch and the stream's EventSource both carry the cookie on their own, so no token is ever in their URLs. No query value is ever a path or a path segment: `agent` must be an own key of the job's `agents`, and every path is derived from job state, a session id that must be a UUID and an agent id that must match `^[A-Za-z0-9_-]{1,100}$`.

Only this repo's project dirs are tried (the slugs of the root, its realpath and the job's worktree under `$CLAUDE_CONFIG_DIR/projects`, else `~/.claude/projects`), never another repo's: the worktree counts only when it is the job's own (`<worktrees.root>/<id>`) or sits under the worktrees dir, as written and resolved, since job.json is agent-writable. A project dir must resolve to exactly `<projects>/<slug>` and the transcript's realpath must stay inside that slug dir (checked at lookup and again when the file is opened, not merely anywhere under the projects dir), and the file is then checked to be a regular file and read through one non-blocking `O_NOFOLLOW` descriptor (held open for the stream's life, so a symlink swapped in later can't redirect it), so a planted symlink or FIFO is a 404.

The owner route answers only for an owner in no daemon session record. The stream counts toward the event-stream cap, is recycled like the others, never receives the pool's frames and stops polling the file when it closes. `/api/state` carries each running agent's last tool call or line of text from the last 64 KiB of its transcript, cached by size and mtime. Transcript text is returned as data inside JSON and SSE frames and rendered as text, or through `md()` for prose, like the session log.

## The page CSP and mockups
The page itself (`/` and `/index.html`) is served with `Content-Security-Policy: frame-src 'self'; frame-ancestors 'none'` and `X-DNS-Prefetch-Control: off`. No other site can frame it, which closes clickjacking: a framed page's own scripts would send signed-in POSTs for whatever a disguised click hit. The page frames only its own origin. The page CSP stops at those two directives, so the inline theme script needs no hash.

Job HTML (mockups) is shown in an iframe with `sandbox=""`, no allow tokens, and `/raw` serves it with `Content-Security-Policy: sandbox; default-src 'none'; style-src 'unsafe-inline'; img-src data:; font-src data:; frame-ancestors 'self'` and `X-DNS-Prefetch-Control: off`. A mockup runs no script at all, so it can't set `location`, open an `RTCPeerConnection` or prefetch through script. The sandbox also blocks `<meta http-equiv="refresh">`, popups, forms and top navigation, and the CSP blocks every subresource load and every connection, so a mockup must be self-contained (inline CSS, `data:` images and fonts) and secrets a misled agent wrote into it aren't sent off the machine when a human opens it.

A clicked link can still navigate the frame itself, and the page's `frame-src 'self'` blocks any other origin there. `/raw` takes `frame-ancestors 'self'` rather than `'none'` because the dashboard's own Files tab frames it. CSS still renders, so state toggles use CSS (`:target`, `<details>`), as the designer prompt says. What stays residual: DNS-prefetch hints in a mockup's markup where a browser ignores `X-DNS-Prefetch-Control`, and a user who copies a URL out of a mockup.

## Job files and screenshots
`GET /api/jobs/:id/file` and `/raw` take a valid job id and a lexically joined path, refuse private job files by name (or by the name a link resolves to), and open every file through `openConfinedLog`: the job dir itself must resolve to `<real root>/.forge/jobs/<id>`, the file must resolve inside it, and it must be a regular file with a single link, read through the one non-blocking `O_NOFOLLOW` descriptor that check opened and re-checked after the open (realpath and inode). A file or directory symlink out, a symlinked job dir, a FIFO, a device or a hard link (to an outside file or a private one) is a 404, and none of them blocks the server. The open runs on Node, which has no `openat`, so a parent directory swapped for a symlink and back within microseconds of the open stays a recorded residual.

`/raw` serves only `.html` files (a log or JSON file served as `text/html` would run as a page) and refuses one over 2 MiB with 413 `file too large`; `/file` serves the last 2 MiB of a larger text file. Screenshot images are served only from a job's `screenshots/` dir, only as PNG/JPEG/WebP (never SVG or other active types), with `nosniff`, a `default-src 'none'` CSP, `Cross-Origin-Resource-Policy: same-origin` (so another site can't embed them, even though its `<img>` would carry a loopback Host), a 10 MiB cap, and the same `openConfinedLog` open as other job files.

## Served assets
The page loads no external scripts, styles or fonts: Tailwind is compiled into the committed `dashboard/dist/`, the three typefaces are vendored woff2 files (`dashboard/fonts/`, OFL) served from the same origin, and the film grain is an inline SVG `data:` URI. The server serves only the page (`no-store`, as built, with no token in it) and the hashed `assets/*.js|css|woff2` files that `dist/manifest.json` lists (never SVG or HTML), matched by exact path and cached immutably. Nothing is served by directory, so the sources, the manifest and the rest of the plugin root never are.
