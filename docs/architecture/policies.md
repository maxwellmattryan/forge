# Policies

## Authorship policy

`lib/engine/guard/attribution.ts` defines what counts as AI attribution: signature lines and trailers, not mentions. It is shared by the Bash `PreToolUse` hook (`hooks/no-ai-attribution.ts`, which blocks before anything is written), by `forge pr open` (which rewrites the messages of the commits it checked from their raw objects, keeping every tree, author and committer, moves the branch only if it still points at the checked commit, then pushes that exact commit with `--force-with-lease` if anything changed), and by the GitHub tracker (which strips issue and comment bodies). On Node older than 22.18 the hook cannot load and exits 1, which Claude Code does not treat as a block, so the policy is not enforced there. The policy is on by default (`aiAttribution: forbid`).

## Review policy

Reviewers tag findings `[blocker] [major] [minor] [nit]`. The CLI decides the verdict from the tags and the repo's `review.blockOn`, not from the reviewer's own first line. This keeps the threshold consistent across lenses and models: "CHANGES over a nit" or "PASS over a blocker" can't slip through. A review without a verdict line is `CHANGES` when its tags already force a round, otherwise `MALFORMED` and re-run once; a second malformed review is counted as `CHANGES` (`--malformed changes`) so a reviewer that cannot follow the format cannot stall the job. A lens with no file is `PENDING` while its reviewer (`reviewer:<lens>` in `job.agents`) has not ended for that review, and `MISSING`, with the expected path, once it has: an agent can claim a review it never wrote, so the orchestrator re-spawns it rather than waiting. `forge job round` and `forge job paths` create the review directory before any reviewer is briefed.

**Model diversity.** A gate that runs on the same model as the builder tends to share its blind spots: it finds the code plausible for the same reasons the builder wrote it. `forge roster` therefore always reports which gatekeepers (the approver, then each panel lens) share the builder's model family. The family is `opus`, `sonnet`, `haiku` or `fable` when the model string names one, else the whole string, with `inherit` resolved through the orchestrator's model. With `runtime.diversity: true`, `forge roster` and `forge init write` turn each overlap into a warning. It never blocks a job: picking models is the human's call. The Balanced init preset already puts the approver on a different family.

## Repo budget

Per-job budgets stop one job; `budget:` (docs/CONFIG.md "Repo budget") caps the repo's spend per UTC day and month. `lib/engine/metrics/spend.ts` sums every `agent-end` usage across live jobs and `.forge/archive/` records, re-priced with today's table, into buckets by UTC day, role and model. `.forge/runtime/spend.json` caches each job's buckets keyed by its events file's size and mtime (an archive record's by `lstat`), plus the cache version and a hash of the price table. It is read through one `O_NOFOLLOW | O_NONBLOCK` descriptor and rebuilt on any mismatch, so a planted symlink or a stale or understated cache is never trusted; `/api/state` and the daemon pool compute the status with `write: false`, so neither writes it. `lib/engine/metrics/repo-budget.ts` turns the ledger into `RepoBudgetStatus` and enforces it in the CLI only, at every place a job starts: `forge job new` (parks the new job), `forge job claim` (parks it and exits 4, unless an agent is running, another live session owns it, or it already waits), `forge next` (starts nothing) and `forge job from-ref` (exits 4). Repo holds reuse `waiting: budget` with a `repo budget:` reason, so the budget notifications fire unchanged. Release (back to `queued`, plus a `resume` when the daemon is on) re-checks the job's own per-job budget, so a session that rewrites its per-job stop's reason to `repo budget:` stays held. A human acknowledges a period with `forge budget ack` or `POST /api/budget/ack`; the ack is a `repo-budget-ack` line in `.forge/runtime/audit.jsonl`, and the effective cap is `cap × (1 + acks)`. Both that command and `forge job new --force` refuse under `FORGE_DAEMON=1`, and `DENY_TOOLS` covers the cache and the audit log.

Residual risk: a session with shell write access could still append a fake `repo-budget-ack` line or forge a fingerprint-matching cache, the same trust level as `forge job budget --ack` ("Request provenance is not authenticated" in [Untrusted input](untrusted-input.md)). A job claimed before the cap trips runs until its next claim, bounded by its per-job budget.

## Usage accounting

The orchestrator records every agent start and end. With Claude Code, `--import` reads the subagent transcript (`<session>/subagents/agent-<id>.jsonl` under `$CLAUDE_CONFIG_DIR/projects`, else `~/.claude/projects`). It looks first under the job's own sessions (the owner's, then the last five in `runs[]`) in this repo's project dirs, and falls back to scanning every project dir for an agent whose parent session isn't recorded. The orchestrator records a background agent's id as soon as it is spawned (`forge job agent <id> attach`), so the dashboard can follow that transcript while the agent runs. Input and cache tokens come out exact, along with tool calls (by unique block id) and duration. Output tokens are estimated from the logged content, because transcripts store the stream's opening usage snapshot. A resumed agent (SendMessage, as the builder is for rework) appends to the same transcript, so each agent record keeps `importedThrough`, the last transcript timestamp imported per agent id, and the next import of that agent counts and times only the lines after it. Without a transcript, the runtime-reported total is used with a blend assumption, and the dashboard shows coverage (how many agent runs reported usage, and how many exactly). Prices live in `lib/integrations/claude/pricing.json` (dated, overridable via `usage.pricing`). For subscription plans they're API-equivalent figures, not a bill.
