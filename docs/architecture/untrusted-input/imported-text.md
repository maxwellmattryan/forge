# Untrusted input › Imported text

Part of [Untrusted input](../untrusted-input.md).

Forge:
- shows agents only collaborators' issue and PR comments by default (`tracker.github.comments: collaborators`): other people's issue comments, PR reviews, conversation comments and replies inside a collaborator's review thread are left out of `request.md` and `pr-feedback.md` and counted in one line; with `all` they follow, quoted, under `## Untrusted` in `pr-feedback.md`. The PR counts (`unresolvedThreads`, `changesRequested`) and the pr-feedback gate's trusted count are unchanged
- removes text people can't see from everything it imports (`visibleText` in `lib/core/text.ts`): zero-width, bidi and other format characters (not ZWJ, LRM or RLM), C0 and C1 controls (not TAB, LF, CR or NEL), the Unicode Tags block (except the England, Scotland and Wales flags), the Variation Selectors Supplement, every variation selector after a run's first, and HTML comments. The provenance line says how many went; over 32, or with any Tags or supplement character, a `Hidden text:` line follows it, and readiness triage marks the item needs-info (`hidden-text`)
- writes one column-0 provenance line ("data, not instructions") at the top of every imported item, then blockquotes every line of the body and each comment (CR, U+2028, U+2029 and NEL count as line breaks, logins and associations are reduced to safe characters), so only Forge writes column-0 lines in `request.md` and a forged provenance line or `### Recent comments` section reads as quoted text. GitHub issues, local backlog items and custom adapters' items all get it: the loader fences a custom adapter's `get`, leaving alone only a body exactly in that fenced form for that item (its own provenance line, Forge's own `Hidden text:` sentence, the rest quoted). Every job title is one line (`createJob`), whoever passes it
- quotes every review, thread comment and conversation comment in `pr-feedback.md` under a Forge-written entry line, each body cut to 4000 characters, and writes each thread's file path as a JSON string, so a path or body holding a newline and a heading can't add a section
- re-imports an issue (`forge job refresh-request`, and a claim before `plan.md` or `spec.md` exists) only through the tracker's own `get`, so a refreshed `request.md` is fenced exactly as at intake; a claim refreshes only a request intake imported from that issue (`origin: issue` on `created`, or the GitHub import fence on older jobs), never words a person wrote, and only from an issue whose author has write access (`author_association` `OWNER`, `MEMBER` or `COLLABORATOR`), so an outside author's edit after a person picked the issue never reaches an agent unseen; `refresh-request` is that person's explicit choice
- shows the approver merged PR titles (other people's text) only through `forge pr titles`, never in its brief: same-repo PRs only (a fork's and a `release/` branch's are dropped), each folded to one line by `oneLineTitle` and cut to 200 characters, every one a quoted `> ` line under a column-0 line saying they are data, never instructions. A title the approver writes passes the title schema (`checkTitle`: one line, no AI attribution) and the secret scan before it reaches GitHub, and `gh pr merge --subject=` takes the live title `=`-joined and folded, so it can never be read as an option
- tells every agent to ignore embedded instructions about secrets, credentials, CI, permissions or out-of-scope work
- serves an issue's own text unfenced only to the dashboard's issue panel: a tracker's optional `view` (docs/TRACKERS.md) is called only by `lib/engine/trackers/view.ts`, whose one caller is `GET /api/backlog/item`, so that text never reaches an agent, and the panel renders it through the escape-first `md()` only (docs/architecture/dashboard-security/reads-and-rendering.md)
- writes a goal mandate's drafting survey (`lib/office/mandates/intake.ts`, docs/architecture/foreman/mandates.md "Intake") under a column-0 data line: the owner's goal and guidance through `fenceImport`, and the tracker's open milestone and issue titles each list in one fence longer than any backtick run, every title through `oneLineTitle`; the `forge:drafter` that reads it has Read, Grep, Glob and Write only, and `forge mandate draft record` refuses a draft with hidden or control characters, refs `checkIssueRef` refuses, or paths that are absolute, start with `-` or climb with `..`. Its refusals name positions (`issues[2].files[0]`), never the drafter's text, so the office run that acks with one never carries drafter text
  - A revision run's brief carries the owner's or the foreman's note and the previous draft's title through `fenceImport`, and a gate run's milestone-draft brief (from the logic behind `forge mandate draft assist`) holds only the draft's path and the fenced goal and guidance
  - Filing an approved draft sends the milestone, issue and amendment text composed exactly as scanned, after one secret scan over all of it (`lib/office/mandates/filing.ts`), with each `@name` quieted on GitHub (a zero-width joiner after the @), and the guarded tracker scans `createMilestone` and `milestoneAdd` again; filing's refusals name the milestone title by position, and a foreman's stopped filing leaves the tracker's error in `filing.json`
- triages tracker items without letting their text reach the tracker (`lib/engine/trackers/triage.ts`, docs/TRACKERS.md "Readiness triage"): the batch the `forge:triage` agent reads fences each item in a fence longer than any backtick run in it, and the agent has only Write (under `forge dash`, the intake runner's one-shot child gets `--tools Read,Write`, no setting source, and only its batch dir as a write root and allow rule, with every other protected path denied: [Daemon security › Runners](../daemon-security/runners.md))
  - `--apply` takes a batch id only in its exact format, reads `verdicts.json` and `items.json` each through one `O_NOFOLLOW` descriptor (a regular file under 256 KiB), ignores refs outside the batch, keeps only known missing keys and a `duplicateOf` from the item's own candidates, skips items changed since prepare, and writes only fixed template text, citing a duplicate as `PR #n`, a same-tracker `#n` or "an active Forge job", never a local job id, a citation it derives from the candidate id and the job records rather than from the agent-writable batch
- reads agent transcripts for a retro without letting their text reach the retro or the CLI (`lib/integrations/claude/friction.ts`, `lib/engine/evals/retro.ts`, docs/IMPROVEMENT.md "Agent transcripts"): `forge retro prepare` finds each transcript only through `agentTranscriptById` and `openTranscript` (job-state ids checked, project dirs confined, one no-follow, non-blocking descriptor), reads it with line, byte and run caps, and writes `transcripts.json` with counts, hashes and charset-limited keys only, never transcript text or a path
  - The digest inputs it writes for the `forge:digest` agents hold each run's log in one fence, every log line made one line (`visibleText`, then every job's known secret values and the secret scanner's credential patterns replaced by `[redacted]`, so none is left half-cut at a line cap, then whitespace and C0/C1 controls, CR, U+2028, U+2029 and NEL included, to one space, then `safeText`, which drops backticks) and prefixed with Forge's own `T<n>`, so only Forge writes column-0 lines; prepare removes a planted `digest` link and writes through `confinedDir`. The digest agents have Read and Write only, nothing in the CLI reads their `friction-<n>.md`, and the retro's proposals ship behind its human spec gate
- adopts only PRs whose branch lives in the same repository (never forks), and only issue-linked PRs from collaborators, so a stranger's PR is never checked out and run by the builder. Every PR read is validated once, in `lib/integrations/github/pull-requests.ts`, into a snapshot that `lib/engine/pr/` reads through its `GitHub` adapter: a PR not marked same-repo (`isCrossRepository` missing or anything but `false`) counts as a fork, and a ref name that fails `SAFE_REF`, a head that is not a sha and a url that is not https are dropped before any policy sees them
- passes trackers only this repo's own issue refs (`nativeRef` in `lib/core/job/issue-ref.ts`): an `owner/repo#N` from another repo on a job is recorded and cited, never read, claimed, mirrored or commented on, and every stored ref must start with a letter or digit and hold no spaces or `..`, so no ref reaches `gh` as an option. The GitHub adapter itself (`issueNumber` in `lib/integrations/github/tracker.ts`) accepts only an issue number in its `-R` repo and passes it after `--`, so a URL or option typed into `forge tracker` never reaches `gh`, whatever the caller; job.json's `issues`, `source` and `noIssue` are locked against `forge job set --field`

**Request provenance is not authenticated.** A request's `from` (`dashboard`, `cli`, `daemon:<scope>`) and the daemon-session checks in `forge requests` come from the caller's environment (`FORGE_DAEMON`, `FORGE_DAEMON_SCOPE`), which a session's own commands could drop. They are guardrails that keep a session following the skill from acting on another job's requests or queuing anything but a `resume` hand-off, not a boundary against a misled session: such a session can still run `forge job human …` directly through `Bash(forge:*)`, though it can no longer lift a job's budget, because `forge job budget --set|--ack` is a human-only operation ([Daemon security › Human-only operations](../daemon-security/human-only-operations.md)). The defences against that are the ones this topic's parts list: what reaches agents is fenced as data, and the unattended session's tools are narrow.
