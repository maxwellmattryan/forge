# Untrusted input › Names and paths

Part of [Untrusted input](../untrusted-input.md).

Forge:
- keeps job ids, branches and bases to `SAFE_REF` (`lib/core/text.ts`: a letter or digit, then `A-Z a-z 0-9 . _ / -`, at most 200 characters), because they fill `{job}`, `{branch}` and `{base}` in shell command templates and reach git argv: command templates (`forge run`, `forge verify`, worktree setup) and `forge worktree create` refuse an unsafe value before anything runs, `forge job new --branch` refuses one before the job exists, and PR adoption refuses a PR whose `headRefName` or `baseRefName` fails it (a `pr-adopt-refused` event names the field, never the value)
  - `forge job set --field` can't write a job's identity (`id`, `branch`, `base`, `worktree`, `port`, `owner`, `schemaVersion`, `createdAt`, `source`, `pr`, `runs`, `usage`, or any key under them), its `effort` (only `forge job effort` writes it, and refuses in a daemon session), its `eval` record and config overlay (only `forge eval start` writes it, and refuses `--set` in a daemon session; every load checks the overlay again and fails closed), a `kind` of `retro` or `eval` (only `forge job new --kind retro` and `forge eval start` create those, because step gives a retro job a fixed review panel and an eval job no PR or escalation gate) or any `__proto__`, `constructor` or `prototype` segment, so a misled session can't point a job at `main` before `forge pr open`. `setJob` enforces these rules through `lib/core/job/fields.ts` for every caller, not only the CLI, and the commands that own those keys write them through its `owned` change instead
  - The extra arguments of `forge run <job> <name> -- <args…>` reach the shell too: each is wrapped in single quotes and never filled again as a placeholder, and an argument containing a quote, backslash or control character (which would end the quoting in sh, bash, zsh or fish), a word before `--`, or any argument with `--background` is refused before anything runs. Arguments are opt-in: a template without `{args}` refuses them, so a configured command that reaches outside systems can't be steered with flags a session picks
  - Arguments are also refused where the template would not keep them as plain words: an `{args}` that isn't a whole unquoted word (inside `'…'` or `"…"`, where `$(…)` expands or a `'` ends the quoting, or after a backslash), or any template with a heredoc, `$'` or `\'`, where `\'` does not close the quote. `forge verify`, worktree setup, background servers, the regenerate build and eval grading have no argument path at all, so arguments can never narrow the gate
- removes a job's root worktree only where Forge computes it (`lib/engine/workspace/worktree.ts`): `forge worktree remove`, `forge sync`'s on-merge cleanup and `forge job delete` act on a stored `job.worktree` only when it is `<worktrees.root>/<id>` and resolves there (`containedWorktree`), so another job's worktree, the main checkout or `<worktrees.root>/<id>` swapped for a link out is refused before anything changes (no checkout undo, no stopped process, no write), and the check runs again right before the delete. A stored path that does not exist is cleared without removing anything. `--delete-branch` checks `job.branch` against `SAFE_REF` up front and deletes only `git.branchPrefix` + id; any other branch (another job's, the base, a `--branch` or adopted PR branch, which may be a human's own) is kept and reported as `branchKept`. A job created before a `worktrees.root` change is refused too: remove its old worktree by hand with `git worktree remove <path>`, and `forge worktree remove <id>` then clears the record
- writes into a job folder's `verify/` and `review/` only through real directories (`confinedDir` in `lib/core/os/fs.ts`): every component from the job folder down is created a level at a time and must then be a real directory, so a link, junction or file that a session or the job's own tests plant there makes `forge verify`, `forge verifiers run|record` and `forge job round|paths|scope` fail with `… is not a real directory` instead of writing through it, and nothing is created in the link's target. The residuals are a swap between the check and the open (Node has no `openat`), a job folder that is itself a link (that needs write access to `.forge/jobs/`, which the write guard refuses to daemon sessions), and the job folder's other subdirectories (`logs/`, `check/`), which are not confined yet
- confines config sinks (`lib/engine/environment/config-sinks-apply.ts`, docs/CONFIG.md "Config sinks") to the job's own worktree: a forged `job.worktree` is refused, every output path must be git-ignored and untracked so job values never reach a commit, a symlink at an output path is replaced rather than followed (the write goes through a randomly named temp file opened exclusively, so a planted entry at a guessed name fails instead of redirecting it), a parent directory or a `from` file that resolves outside the worktree is refused, as is a `from` that is a symlink or a hard link and a hard-linked output path that a merge with no `from` would read as its base, and no rendered value reaches a result, an event, an error or a log header
  - Residual risk: the confinement checks and the write or read are separate syscalls (Node has no directory handle with `openat`/`O_NOFOLLOW`), so a same-user process that swaps a parent directory or `from` for a symlink in between wins the race; the worktree and the job's own session are already that user

**One wrapper per tool.** Every git, gh and docker process in `lib/` starts in one module, so no call site can forget a pin, a clean environment or a timeout. `lib/integrations/git/runner.ts` prepends `-c core.fsmonitor=false -c core.quotepath=off -c diff.interHunkContext=0 -c diff.suppressBlankEmpty=false -c diff.relative=false` to every call: the worktree's config can't run an fsmonitor program or reshape output a parser reads, and the diff pins are git's defaults, so they only override a user's or a worktree's config.
- Without a caller's own `env`, each call drops the inherited `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_COMMON_DIR`, `GIT_OBJECT_DIRECTORY` and `GIT_NAMESPACE` (Forge run from a git hook would otherwise act on another repo), and a read runs with `GIT_OPTIONAL_LOCKS=0`, so it never locks the index of a worktree whose builder is running git at the same moment. Call-specific options stay at their call sites (`core.hooksPath` on member git, `--no-ext-diff`, `--no-textconv`).
- `lib/integrations/github/gh.ts` gives every gh call a 60 s timeout unless the call sets a shorter one (the actor lookup and the release check 5 s, the link preview 15 s), so a hung gh can't block `pr sync` or a tracker call, and parses JSON output in one place.
- `lib/integrations/docker/runner.ts` holds the sync runner `lib/engine/environment/backing.ts` uses, an async runner and the streaming spawn behind the dashboard's container logs; Docker's state travels as `docker` in `forge backing status <job>` and as the error codes `docker_missing` and `docker_stopped`, never as message text. The release scripts share the git pins through `scripts/git.ts`.
