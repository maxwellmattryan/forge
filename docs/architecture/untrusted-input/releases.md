# Untrusted input › Releases

Part of [Untrusted input](../untrusted-input.md).

Forge:
- treats `forge release`'s runtime files as data (`lib/engine/release/run.ts`, docs/RELEASES.md "Releasing a project"): `release.json` and `state.json` in `.forge/runtime/release/` are writable by any session, so `forge release run` recomputes the plan from the main checkout's config and the clones and refuses when either file's hash differs, takes every command and check from that recomputation, runs each step's check before the step so an edited state can't publish twice, asks before every publish step without a terminal override (`release.publish: allow` is a hand edit of config; the question stops accidental publishes from agent sessions, not a determined one that fakes a terminal), refuses a symlinked release dir or file, and is refused in a daemon session. Without a terminal, the one stand-in for the question is a foreman `release-approval` for the recomputed plan's hash in a repo that delegated the `release` gate class (["Foreman"](../foreman.md)); a process that can append to the job's `events.jsonl` can forge one there, though not change what runs, and in a repo that did not delegate a forged approval does nothing
- treats the release records in `events.jsonl` as data (`lib/engine/release/interim.ts`, `lib/engine/release/interim-apply.ts`, docs/CONFIG.md "Interim strategies"): only the `FORGE_DAEMON`-refused `forge job interim release` and a `--job` `forge release run` write `interim-released` (both refuse in a daemon session), and the run takes the version only from checks it ran itself, never from `state.json`
  - Every reader validates `interim-released` and `interim-bumped` (repo keys, a semver version of at most 120 characters that names no canary), so `-Zunstable` or `1.2.0 && x` is ignored; the release bump refuses a record whose dependency's recorded PR is not MERGED, writes manifests through `writeManifest` and never through a symlinked manifest or lockfile, runs the lockfile refresh with a fixed argv and no shell (`lockfileArgv` refuses a name or version that starts with `-`; npm always gets `--ignore-scripts`), puts every file back when the refresh fails or touches another path, and commits with `--no-verify --only -m`, so no hook, template or trailer config adds attribution
  - A forged `interim-bumped` only flips the pure gate: `forge pr open` (`interim_stale`) and `forge pr ready` (`release_gate`) read the consumer's manifests from git and refuse one that doesn't name the release. Accepted residuals: a forged, well-formed `interim-released` for a merged dependency bumps the consumer to a version that exists (the posture a local or sequential record already has); a planted tag satisfies the cmake tag check; and cargo and npm read builder-writable project config during the refresh, as verify's own commands do. No publish or release command ever runs from the bump.
