## Behaviours
- B1. `statusKey(job)` collapses stage/state into a tracker status: `{ state: 'running', stage: 'build' }` → `'in-progress'`; `{ state: 'waiting', stage: 'spec', waitingOn: 'spec-approval' }` → `'blocked'`; `{ state: 'waiting', stage: 'plan', waitingOn: 'split-approval' }` → `'blocked'`; `{ state: 'waiting', stage: 'pr', waitingOn: 'pr-review' }` → `'review'`; `{ state: 'done', stage: 'done' }` → `'done'`. Old: trackers › status keys and project option matching; split-gate › split-approval is a waiting reason jobs can park on and leave
- B2. The full rule, in order (source; each step should get a row): state `done` → `'done'`; state `cancelled` → `'cancelled'`; stage `pr` → `'blocked'` when `waitingOn === 'conflicts'`, else `'review'`; state `waiting`, `blocked` or `failed` → `'blocked'`; state `queued` or stage `backlog` → `'queued'`; anything else → `'in-progress'`. Old: none beyond B1 (source)
- B3. `STATUS_KEYS` is `['queued', 'in-progress', 'review', 'blocked', 'done', 'cancelled']`, and every value `statusKey` can return is in it. Old: engine-ts › the deprecated tracker status paths re-export lib/api/tracker.ts (key set); source for the values
- B4. `lib/api/tracker.ts` exports exactly `STATUS_KEYS` and `statusKey` (sorted `Object.keys` of the module); `lib/trackers/status.mjs` and `lib/trackers/status.ts` export exactly the same two names and the same objects (`shim.statusKey === real.statusKey`, `shim.STATUS_KEYS === real.STATUS_KEYS`), so custom adapters that import the old paths keep working. ## Edge and corner cases
- E1. (No setup: plain objects.) Precedence corners of `statusKey` (source): `{ state: 'done', stage: 'pr' }` → `'done'` (state done beats stage pr); `{ state: 'cancelled', stage: 'pr', waitingOn: 'conflicts' }` → `'cancelled'`; `{ state: 'waiting', stage: 'pr', waitingOn: 'conflicts' }` → `'blocked'`; `{ state: 'failed', stage: 'pr' }` → `'review'` (the pr rule comes before the failed rule); `{ state: 'running', stage: 'backlog' }` → `'queued'`; `{ state: 'queued', stage: 'build' }` → `'queued'`; `{ state: 'waiting', stage: 'backlog' }` → `'blocked'`; `waitingOn` absent or null is accepted. Old: none (source)
- E2. (No setup.) `statusKey` reads only `state`, `stage` and `waitingOn`: a `Pick` of those three works without a full Job. Old: trackers › status keys and project option matching (plain objects)
