Domain logic behind a command is inventoried with its domain module; this file records each command's routing, argument parsing, exits and JSON, plus the logic that lives in lib/cli/commands/ itself (forge git, init/migrate, advance, requests, tracker/next/sync, daemon status/log, dash, focus, the renderers). `dispatch`/`main` themselves (lib/cli/main.ts) belong to cli.md; where an item below names a dispatch rule it is the per-command contract dispatch applies.

## Behaviours

### Arguments and output (args.ts)
- B1. `parseArgs(['--x'])` → `{x: true}`; `['--x=']` → `{x: ''}`; `['--x','1','--x','2']` → `{x: ['1','2']}` (repeats become arrays); `['--a','--b','v','p']` → `a: true` (a value starting with `--` is never swallowed), `b: 'v'`, `pos: ['p']`; everything after `--` is positional. Old: args › "parseArgs: bare, empty and repeated flags"
- B2. Boolean flags never take the next word as a value: json, help, pretty, include-text, csv, done, dry-run, clear, no-issue, verify-only, confirm, quiet. `parseArgs(['dash','--quiet','x'])` → `quiet: true`, `pos: ['dash','x']`; `forge job show --json <id>` keeps the id (exit 0). Old: args › "--quiet takes no value"; cli-contract › "the spawned CLI › --json success output is one JSON value"
- B3. `str(undefined,'--job')` → undefined; `str('j1')` → 'j1'; `str('--weird')` → '--weird'. Old: args › "str: missing values and repeats fail, strings pass through"
- B4. `num(undefined)` → undefined; `num('0','--tokens')` → 0; `num('1.5','--duration-ms')` → 1.5; `num('20','--limit',{integer:true})` → 20. Old: args › "num: non-negative numbers, with an integer mode"
- B5. `oneOf('a',['a','b'],'action')` → 'a'. Old: args › "oneOf: missing and unknown values name the allowed set"
- B6. `withoutMode` strips only Forge's `--mode` before `--`: `['job','show','--mode','human','x']` → `['job','show','x']`; `['--mode=agent','version','--json']` → `['version','--json']`; `['git','log','--mode','human','-1']` → `['git','log','-1']`; `['run','x','test','--mode','human','--','a','--mode','b','--mode=c']` keeps everything after `--`; `['job','list','--mode','--json']` → `['job','list','--json']`; `['job','list','--mode','--','x']` → `['job','list','--','x']`; `['job','list','--mode']` → `['job','list']`; `--moderate` stays. Old: output-mode › "withoutMode strips only Forge's flag"
- B7. `resolveOutputMode(argv, env, isTTY)` precedence: `--json` (before `--`) → agent whatever `--mode`/`FORGE_MODE`; then `--mode`; then `FORGE_MODE` (empty = unset); then TTY → human, pipe → agent. Cases: `['--mode','human']`+FORGE_MODE agent, no TTY → human; `['--mode=agent']`+FORGE_MODE human → agent; FORGE_MODE human, no TTY → human; FORGE_MODE agent, TTY → agent; `['run','x','test','--','--mode','human']` pipe → agent; `['run','x','test','--','--mode=fancy','--json']` TTY → human; `['job','show','--mode','human','mode-job']` → human. Old: output-mode › "resolveOutputMode: precedence"
- B8. `lenientOutputMode` never throws: a bad `--mode` falls through to FORGE_MODE (`['--mode=fancy']`+FORGE_MODE human → human), a bad FORGE_MODE falls through to the TTY (`FORGE_MODE: 'loud'`, TTY → human). Old: output-mode › "resolveOutputMode: bad values are usage errors"
- B9. `out(data, flags)`: a string prints raw with one trailing newline (JSON-encoded under `--json`); anything else is compact JSON in agent mode (indented with `--pretty`); in human mode (and no `--json`) the outer call's registered renderer's text, else the generic `render`. Old: cli-contract › "--json success output is one JSON value" (`worktree path` raw `'\n'` vs `--json` `""`; `job get <id> title` raw `'Status row\n'` vs `"Status row"`; `config get tracker.kind --json` → `"none"`)

### Help and the error contract (help.ts)
- B10. `forge help`, `forge --help` and bare `forge` print the same overview (exit 0, stderr empty), outside any repo and without FORGE_ROOT. It contains `forge status [--all]`, `--json`, `docs/CLI.md`, the line `0 ok · 1 failed · 2 usage · 3 owned · 4 blocked · 5 external`, a `  forge <name>` line per group, the usage line `Usage: forge <command> [args] [--json] [--mode human|agent] [--help] [--pretty]`, a `Global flags:` block with `  --mode human|agent  output for a terminal…`, and the job group's subcommands alphabetically (`/^  forge job acs\|advance\|agent\|[^\n]*\|step\|verdicts\b/m`). Old: cli-contract › "the spawned CLI › help: overview, group, command", "help works outside a repo, without FORGE_ROOT"; output-mode › "help documents --mode"
- B11. `forge help job` == `forge job --help`; it includes `forge job advance <id> --session S [--epoch N] [--max N]` and `Run forge help job <subcommand> for flags and exit codes.`. `forge help job step` == `forge job step --help` == `forge job step some-id --help` and contains `forge job step <id> [--session S]`, `Flags:`, `--session`, `Exit codes:` with rows for 0 and 2. `forge help job nope` prints the group help. Old: cli-contract › "help: overview, group, command"
- B12. `--help` anywhere before `--` wins over running the command; `forge git log --help` / `forge git diff --help` print Forge's help (starts `forge git <sub> `, has `Exit codes:`) and never start git. Old: cli-contract › "forge git keeps --json and --help to itself"
- B13. `forge help … --json`: `help job step --json` → the command object (`command: 'job step'`); `help job --json` → the group (`name: 'job'`); `help --json` and bare `--json` → `{version, groups}` with groups in `GROUPS` order. A command object carries only `command, args, summary, flags, exits, docs` keys; `readme` never appears. Old: cli-contract › "help: overview, group, command"; dash-activity › "help documents --quiet"; dev-flow › "forge dash --dev › help documents --dev"
- B14. Every command's help lists exits 0 and 2 plus its own; minimum sets: job claim 3,4; job advance 1,3; verify 1; requests claim 3; job link 3; worktree create 5; pr merge 1. Every help-table row: exit codes only from 1,3,4,5, each once; `command` starts with its group name; `summary` non-empty and one line; `renderCommand` of every command includes `--mode human|agent` (global flags appended; a command's own entry for a global flag, e.g. version's `--json`, replaces the generic line). Old: cli-contract › "help lists each command's exits"; output-mode › "help documents --mode"
- B15. The help groups are exactly the commands dispatch routes plus help, version and update; `findHelp(['job','step']).command.command` → 'job step'; `findHelp(['nosuch'])` → null. An unknown subcommand gives a usage error listing the group's subcommands sorted: `forge job bogus` → exit 2, stderr contains `usage: forge job acs|advance|agent|archive|assist|audit|budget|claim|decision|delete|effort|findings|from-ref|get|handoff|human|interim|link|links|list|new|note|panel|paths|progress|prune|refresh-request|release|repo|round|scope|score|set|show|step|verdicts; run \`forge help job\``. Old: cli-contract › "help covers every routed command"; advance › "job usage and help list advance"
- B16. `toCliError(err, argv)`: a non-ForgeError → `{code:'internal', message, exit:1, hint:null}` (`Error('boom')` → message 'boom'; a thrown string → that string). A usage ForgeError gets the help of the longest known prefix: `['job','claim','x','--json']` → hint 'forge help job claim'; `['job','nope']` → 'forge help job'; `['nope']` → 'forge help'; a hint set where it was thrown wins ('forge help pr'). Default hints: unknown_command 'forge help', not_initialized '/forge init'. Old: cli-contract › "ForgeError codes and exits"
- B17. Exit/error table through the spawned CLI (repo with a job held by session A, a dependency, a job blocked on it, and a failing `git` stub exiting 128): `job bogus` → 2 usage hint 'forge help job'; `job claim <held>` (no --session) → 2 usage 'forge help job claim'; `nosuch` → 2 unknown_command 'forge help'; `status` in an uninitialised repo → 2 not_initialized '/forge init'; `job claim <held> --session B` → 3 owned null; `job claim <blocked> --session S` → 4 blocked null; `worktree prune` with failing git → 5 external null; `job show no-such-job` → 1 not_found null. Old: cli-contract › "the spawned CLI › exit codes follow the table"
- B18. `--json` errors: stdout is exactly one line `{"error":{"code","message","exit","hint"}}` with keys in that order, stderr empty, `exit` equals the process status; quotes and newlines in the message survive the round trip. Without `--json` in agent mode: stdout empty, stderr `forge: <message>\n` (`forge: unknown command "nosuch"; run \`forge help\` to list commands\n`). `FORGE_DEBUG=1` adds the stack (`\n    at `) on stderr in both modes; with `--json` stdout stays one JSON line. Old: cli-contract › "--json errors go to stdout only", "text errors are unchanged; FORGE_DEBUG adds the stack"
- B19. Human-mode errors (`reportError`): `error: <message>` then `fix: <hint>` on stderr, stdout empty: `job show nope --mode human` → exit 1, stderr `/^error: no job "nope"[^\n]*\n$/`; `job claim mode-job --mode human` → exit 2, stderr `/^error: [^\n]+\nfix: forge help job claim\n$/`; `--json` still wins (one JSON line, code not_found). A bad `--mode` under FORGE_MODE=human is reported in human mode: `error: unknown output mode "loud" (human, agent)\nfix: forge help job show\n`. Old: output-mode › "human mode errors: error and fix lines", "the CLI in each mode › human mode reports an error with error and fix lines"
- B20. KEPT: README's generated CLI table equals `readmeTable()`, `syncReadme(readme)` is a no-op, each row's usage and summary appear in its `forge help`, and `syncReadme('# no markers\n')` throws `/no <!-- forge:commands:start/` (kept, not rewritten: test/invariants/cli-contract.test.ts). Old: cli-contract › "README CLI table is generated from the help tables"
