## Behaviours

### Output mode and argv (main)
- B1. `main()` resolves the output mode once per process with `resolveOutputMode(rawArgv, process.env, stdout.isTTY)`, then strips `--mode` with `withoutMode` so help, git and `run`'s args never see it; `dispatch` never re-resolves it: with the mode set to `agent`, `dispatch(['job', 'list', '--mode', 'human'], ctx)` leaves `outputMode() === 'agent'` and its data prints as JSON (first row id `mode-job`). Old: output-mode › dispatch never re-resolves the mode
- B2. `resolveOutputMode(argv, env, isTTY)` precedence (exact table): `['job','list','--json','--mode','human']`, TTY → `agent` (`--json` beats `--mode human`); `['--mode=human','--json']`, FORGE_MODE=human → `agent`; `['--mode','human']`, FORGE_MODE=agent, no TTY → `human` (`--mode` beats FORGE_MODE); `['--mode=agent']`, FORGE_MODE=human → `agent`; `['version']` FORGE_MODE=human no TTY → `human`; FORGE_MODE=agent TTY → `agent`; FORGE_MODE `''` TTY → `human` (empty counts as unset); no env, TTY → `human`; no env, no TTY → `agent`; `['run','x','test','--','--mode','human']` no TTY → `agent` (nothing after `--` counts); `['run','x','test','--','--mode=fancy','--json']` TTY → `human`; `['job','show','--mode','human','mode-job']` no TTY → `human` (`--mode` takes its value, not the next positional). Old: output-mode › resolveOutputMode: precedence
- B3. Bad mode values are usage errors (ForgeError `code: 'usage'`, `exitCode: 2`, message containing `human, agent`), with or without a trailing `--json`: `['--mode']`, `['job','list','--mode']`, `['--mode','--json']`, `['--mode','human','--mode','agent']`, `['--mode=human','--mode=human']`, `['--mode=']`, `['--mode=fancy']`, `['--mode','job-12']`, and env `FORGE_MODE=loud`. Messages: `unknown output mode "job-12" (human, agent)`, `unknown FORGE_MODE "loud" (human, agent)`. `lenientOutputMode` never throws on the same inputs: a bad flag falls through to FORGE_MODE (`['--mode=fancy']` + FORGE_MODE=human → `human`), a bad FORGE_MODE falls through to the TTY (`[]` + `loud` + TTY → `human`). Old: output-mode › resolveOutputMode: bad values are usage errors
- B4. `withoutMode(argv)` strips only Forge's flag and its value: `['job','show','--mode','human','x']` → `['job','show','x']`; `['--mode=agent','version','--json']` → `['version','--json']`; `['git','log','--mode','human','-1']` → `['git','log','-1']`; after `--` nothing is touched (`['run','x','test','--mode','human','--','a','--mode','b','--mode=c']` → `['run','x','test','--','a','--mode','b','--mode=c']`); a bare `--mode` before another flag or `--` drops only itself (`['job','list','--mode','--json']` → `['job','list','--json']`; `['job','list','--mode','--','x']` → `['job','list','--','x']`; trailing `['job','list','--mode']` → `['job','list']`); other flags like `--moderate` stay. Old: output-mode › withoutMode strips only Forge's flag
- B5. Agent mode output is identical whichever way it is selected: for `version`, `job list`, `job show <id>`, `status`, `worktree path <id>`, `help`, and the failing `job show nope`, the spawned CLI's `{status, stdout, stderr}` with FORGE_MODE unset (stdout a pipe) equals FORGE_MODE=agent and `--mode agent`; `--json` under FORGE_MODE=human equals `--json` alone; agent errors keep the `forge: ` stderr prefix (exit 1 for `job show nope`). Old: cli-contract › the spawned CLI › agent mode is today's output, whatever selects it
- B6. Human mode renders results (`FORGE_MODE=human` or `--mode human`): `job show mode-job` first line `mode-job  Mode job` with a `Stage` line; `version` → `forge <version>\n` (agent: `{"version": "<version>"}`); `job list` starts with the first row key and has a line matching `/mode-job +backlog +.* Mode job$/`; `status` starts `job +stage +state +round +tasks +pr +session`; none of these contain `{`, `"` or ESC. `worktree path` prints the same in both modes. `--json` beats human (JSON output). Old: output-mode › human mode renders results; --mode does not swallow a positional; output-mode › the CLI in each mode › human mode renders a result; …› FORGE_MODE=human selects human output
- B7. Errors by mode: human mode → stdout empty, stderr `error: <message>\n` (e.g. `error: no job "nope"…`), plus `fix: forge help <group> <cmd>\n` for usage errors (`job claim mode-job --mode human` exits 2 with `error: …\nfix: forge help job claim\n`); a bad `--mode loud` under FORGE_MODE=human renders `error: unknown output mode "loud" (human, agent)\nfix: forge help job show\n` with exit 2; `--json` beats human for errors: one JSON line on stdout (`error.code: 'not_found'`, exit 1), stderr empty. Agent text errors: stdout empty, stderr `forge: <message>\n`; `FORGE_DEBUG=1` appends a stack (`\n    at …`) to stderr, and with `--json` the JSON line stays alone on stdout while the stack goes to stderr. Old: output-mode › human mode errors: error and fix lines; output-mode › the CLI in each mode › human mode reports an error with error and fix lines; cli-contract › the spawned CLI › text errors are unchanged; FORGE_DEBUG adds the stack; …› --json errors go to stdout only
- B8. `forge --mode job-12` (a bad mode where help would otherwise run) exits 2 with `unknown output mode "job-12" (human, agent)` and prints no `Usage: forge` help. Old: output-mode › the CLI in each mode › forge --mode <id> is refused, not help
- B9. The render key is chosen once in `main()` from the positional words; `dispatch` never sets it: after `setRenderKey('verify')`, `dispatch(['job','list'])` leaves it `'verify'`; after `setRenderKey(undefined)`, `dispatch(['job','show','reg-job'])` leaves it undefined. Old: render-registry › dispatch never sets the render key

## Edge and corner cases
- E1. (Setup: B23–B28's fixed `now`, `color: false`, inbox state baseline first.) Old: activity › activity log › escapes control characters and caps long text
- E2. (No setup: pure `formatActivity`/`jobEventParts` calls.) Old: activity › activity log › escapes control characters and caps long text
- E3. - E4. (Setup: B30's fake pool with a listener that throws.) Old: none (source)
- E5. (Pure call: `withoutJson(['git','log','--','--json'])` → `['git','log','--','--json']`.) `withoutJson` removes only Forge's `--json` (not one after `--`), so `forge git log -- --json` still passes `--json` as a path. Old: cli-contract › the spawned CLI › forge git keeps --json and --help to itself
- E6. (Pure: `parseArgs(['pr','merge','--now','j1'])` gives `flags.now === 'j1'`, which main treats as not-now and as a missing id.) `forge pr merge --now <id>`: parseArgs would read `<id>` as the flag's value, so `--now` is honoured only when it is the boolean `true`, never a string. Old: none (source)

## Cheapest layer
- In-process: B1–B4, B9, B17–B19 (call `dispatch` with `{ root, config, initialized }` from `loadConfig`), all activity items (B23–B30, E1–E4) with fake pools and a temp `.forge/jobs/` dir; set and restore `setOutputMode`/`setRenderKey` in `finally`, outside any concurrent `describe`.
- `forgeInProcess` (test/support/in-process.ts) runs `dispatch` and maps errors through `toCliError`: use it for B15, B16, B19 refusals (exit code + error code). It refuses `config`, `dash`, `daemon`, `git`, `help`, `version`, `update`, `--help` and `--mode`, so those need a spawn.
- Spawned CLI (`forgeAsync`), one each: B5 (agent-mode equivalence over a few commands), B7 (human error lines, `FORGE_DEBUG` stack), B8, B10 (help outside a repo: empty temp dir, `FORGE_ROOT` deleted from env), B11 (git passthrough with a git stub on PATH), B13/B14 (daemon session: `FORGE_DAEMON=1` + `FORGE_DAEMON_TRUST`), B20 (status table text).
- No HTTP server needed here: the server's `onRequest` hook (reporting requests, never breaking a response when it throws) is server.md's; `requestLine`/`requestLogger` are tested with plain `RequestInfo` objects.

## Setup recipes
- Repo with one job: `repoTemplate(dir => { write answers {tracker:{kind:'none'}, pr:{enabled:false}, worktrees:{root:'../{repo}.wt'}}; forgeSync(dir, ['init','write','--answers',file]); forgeSync(dir, ['job','new','--title','Mode job','--ref','mode-job']) })`.
- Capturing output in-process: temporarily replace `process.stdout.write`/`process.stderr.write`, collecting string chunks and passing Buffer chunks (the test runner's frames) through; restore in `finally`.
- Activity: a fixed `now: () => new Date(2026, 9, 19, 9, 5, 7)`; strip colours with `/\x1b\[[0-9;]*m/g`. Session state objects need `{ scope, running, status, pid, held, waiting, lastError, permissions }` (others may be null). A fake pool is `{ subscribe(fn) { add; return unsubscribe }, emit(e), state?() }`. Events are JSON lines `{ v: 1, ts, type, ... }` in `<root>/.forge/jobs/<id>/events.jsonl`; poll with `waitFor` and a short `intervalMs` (20).
- Daemon-session spawn: env `{ FORGE_DAEMON: '1', FORGE_DAEMON_TRUST: trustDigest(dir) }` (`TRUST_ENV`, `trustDigest` from `#core/config/load.ts`).
