## Cheapest layer
Everything is in-process except:
- One spawned `forge config set` (routing, exit 0, stdout JSON, audit actor from `FORGE_ACTOR`), one refused `forge config set` (exit 1, key on stderr), `forge config set` without `.forge/` (exit 2, `/forge init`), one `forge config get` (raw string vs JSON list), one `forge config validate` (exit 1 with problems / exit 0) — use `forgeAsync`. `forge config` cannot go through `forgeInProcess` (it prints for itself; MAIN_ONLY), so call `configCmd` behaviours through `setConfigValue`/`parseCliValue`/`fieldFor` in-process and keep the spawned checks to those five.
- The daemon trust refusal (B49) needs a spawned CLI with `FORGE_DAEMON=1` because `main()` runs `daemonTrust` before `dispatch`; one test covering changed config, tracker symlink and missing digest is enough. `daemonTrust` itself is in-process (pass `env`).
- B4 migrations and B2 loading need a temp dir with `.forge/config.yml` (no git needed); use `loadConfig(dir, { text })` where the bytes are all that matter.
- B15 custom trackers, B10 reviewer checklists and B48 trust digests need a temp dir with files under `.forge/trackers/`, `.forge/reviewers/`, `.forge/verifiers/`, `.forge/secrets-allow.txt`.
- B73/B74 need stub executables in temp dirs (POSIX exec bit; the win32 cases pass `platform: 'win32'` and only stat).
- HTTP mapping of `ConfigSetError.reason` (locked → 403, unknown/invalid → 400, unsupported-yaml → 409) is the server's (server.md), not this module's.
- Run-time sink application (config-sinks-apply: refusing unsafe paths, git-ignore checks, redaction) is engine/environment's and cli.commands' (`forge run`), not here.

## Setup recipes
- Config objects: `defaults()` from `#core/config/load.ts`, mutate, then `validateConfig(c, dir)`; filter problems by prefix. For a root with no reviewer overrides use a fresh `tempRepo()` dir or `fs.mkdtempSync` (this repo's own `.forge/reviewers/design.md` would shadow the plugin's in B10).
- Commented config: `test/fixtures/config-commented.yml` (schemaVersion 2; has `pipeline:` ending in `  budget:\n    tokens: null\n    verifyRetries: 2` then a blank line; `runtime:` before `tracker:`; `review.blockOn` as a block list followed by `  panel:`; `tracker.github.ready.labels: []  # all must match` followed by `milestone: null`). Copy it into `<repo>/.forge/config.yml` via `repoTemplate`; compare bytes before/after for every refusal.
- `set` the way the CLI does: `setConfigValue(dir, key, parseCliValue(fieldFor(key), raw), () => ({ login: 'x', source: 'env' }))`. Audit log: `<dir>/.forge/runtime/audit.jsonl`, one JSON per line; `EVENT_SCHEMA_VERSION` from `#core/job/schema.ts`.
- Old-version configs: write YAML with `schemaVersion: N` and the comment `// old-version fixture` on that source line (schema.test's literal tripwire, kept, requires it).
- Effort tables: `test/effort-cases.ts` (EFFORT_CASES, ROLE_EFFORT_CASES, INVALID_EFFORTS) belongs to this module and is kept for the builders (dashboard's effort mirror imports it too); its values are also copied into B37–B39. ROLE cases are applied with: `config = defaults(); Object.assign(config.runtime, rest); Object.assign(config.runtime.efforts, efforts); Object.assign(config.runtime.effortByComplexity, effortByComplexity); panel effort set on the `security` entry`.
- Sink ctx: `{ job: 'j1', port: 4123, worktree: '/wt/j1', branch: 'forge/j1', base: 'main', component: { name: 'api', path: 'services/api', dir: '/wt/j1/services/api' } }`; no-port ctx = same with `port: null`.

- Custom tracker adapter: write `<dir>/.forge/trackers/acme.ts` exporting `default { name: 'acme', list() {…}, … }` (any content suffices for validation and digest checks).
