## Behaviours

### lock.ts
- B1. `withLock(lockDir, fn, {timeoutMs=10000})` creates the parent dir, takes the lock by `mkdir`, writes `<lockDir>/holder.json` `{v:1, pid, startedAt (this process's start), host: os.hostname(), token}`, runs `fn`, returns its value and removes the lock. Inside `fn`, `readLockHolder(lockDir)` → `{pid: process.pid, host: os.hostname(), …}`. Old: test/lock.test.ts › "the lock proves death › release only removes its own lock"
- B2. Mutual exclusion across processes: 4 child processes (`test/fixtures/lock-child.ts`) contending on a lock planted with a dead holder each enter exactly once, and the log alternates `enter <tag>` / `exit <tag>` (8 lines, never two enters in a row); the lock dir is gone afterwards. Old: test/lock.test.ts › "the lock proves death › two waiters on a stale lock: one holder"
- B3. A lock is never broken for its age: a live holder (`tryLock`) whose dir mtime is 10 min old keeps it; a waiter with `timeoutMs` 500 fails with `ForgeError` `timed out waiting for lock <lockDir> (held by pid <n>)` (exit 1) and never enters. The message says `holder unknown` when no holder was read. Old: test/lock.test.ts › "the lock proves death › a section longer than the old 60 s limit keeps its lock"
- B4. Death-proof table (`withLock` with a 300 ms timeout; "enters" = the lock was broken):
  - live holder (this pid, matching `startedAt`), dir mtime 1 h old → does not enter
  - holder on another host (`another-host.invalid`) with a dead pid → does not enter
  - dead holder with a `breaking/` marker in the dir (another breaker mid-break) → does not enter
  - holder whose pid has exited → enters
  - (POSIX) live pid whose `startedAt` is 1 h off the real start (pid reused; slack `START_SLACK_MS` = 30 s) → enters
  - no holder.json, dir mtime fresh → does not enter; mtime 61 s old → enters (60 s legacy rule, the only place age counts)
  - garbage holder.json (`{"v":1,"pid":"x"}`) fresh → does not enter; `{not json` with mtime 61 s old → enters (garbage gets only the legacy rule)
  Old: test/lock.test.ts › "the lock proves death › death proof cases"
- B5. `lockHeld(lockDir)`: no dir → false; a live holder → true, and the probe leaves the dir untouched (same inode); a dead holder → false and the probe breaks nothing (dir still there); a non-directory lock path → true; a holder-less dir → true while its mtime is within 60 s. Old: test/lock.test.ts › "the lock proves death › lockHeld reads the lock without taking it"
- B6. Release removes the lock only while `holder.json` still carries this holder's token: if another token was written during `fn`, the dir stays with that token. `tryLock` → `{release}` on success (release is idempotent and token-checked) or, when held, `{holder: {pid, host}}` (this process's pid and hostname for its own lock; nulls when the holder never wrote holder.json, after ~200 ms of retries). Old: test/lock.test.ts › "the lock proves death › release only removes its own lock"
- B7. `withLockAsync` is `withLock` for an async `fn`, polling every 50 ms without blocking the event loop, same timeout and release rules. Old: none (from source)
- B8. A live holder's lock is never broken however far the clock jumps: with `tryLock` held and `Date.now` moved +3 h, `withLock(…, {timeoutMs:300})` throws `timed out waiting for lock`. Old: test/reconcile.test.ts › "a clock jump forward"
- B9. `readLockHolder(lockDir)` → the holder, or null for a missing, oversized (> 4096 bytes), non-regular (FIFO, symlink — opened `O_NOFOLLOW|O_NONBLOCK`) or malformed file: `v` must be 1, `pid` a positive integer, `host` a string, `token` a non-empty string ≤ 100 chars, `startedAt` a parseable date. Old: test/lock.test.ts › "the lock proves death › death proof cases" (garbage holder); test/reconcile.test.ts (sync reads the daemon lock holder without taking it)

### process.ts
- B10. `run(cmd, args, opts)` spawns without a shell and returns `{ok, stdout, stderr, status}`. A non-zero exit without `allowFail` → `ForgeError` code `external` (exit 5) `<cmd> <shownArgs…> exited <n>: <stderr or stdout, trimmed>`; with `allowFail` → `{ok:false, …, status:n}`. A binary that cannot start → `ForgeError` `external` `<cmd> failed to start: <message>` (`allowFail` → `{ok:false, stdout:'', stderr:<message>, status:null}`). `shownArgs` replaces `args` in messages. Old: test/cli-contract.test.ts › "ForgeError codes and exits" (`forge-no-such-binary-xyz` → `failed to start`, exit 5; `node -e process.exit(3)` → `exited 3`, exit 5)
- B11. Old: test/config-sinks-run.test.ts › "config sink commands › a command that exits without reading its stdin keeps its exit status"
- B12. `timeoutMs`: a hung child is killed; without `allowFail` → `ForgeError` `external` `<cmd> <first arg> timed out after <ceil(timeoutMs/1000)> s` (300 ms → `1 s`); with `allowFail` → `{ok:false, stdout:'', stderr:<that message>, status:null, timedOut:true}`. `timedOutMessage('gh', ['api','user'], 300)` → `gh api timed out after 1 s`. Old: test/gh.test.ts › "a hung gh times out" (through the gh runner)
- B13. `findOnPath(cmd, env, platform)` (stat/access only, nothing runs): returns the first executable regular file on `env.PATH` (or `env.Path`); empty and relative PATH entries are skipped; directories with the tool's name are skipped; a `cmd` containing `/`, `\` or NUL → null; missing → null. - B14. `pidAlive(pid)`: false for `0`, `1`, `-1`, `-process.pid`, `1.5`, `NaN`, `'123'`, null, undefined and an exited pid; true for `process.pid`. Signals the group first, then the pid; EPERM counts as not alive. Old: test/lock.test.ts › "pidAlive is false for pids that are not a real process id"
- B15. `killAndWait(pid, graceMs)` and `killAndWaitAsync` SIGTERM the process group, wait up to `graceMs`, then SIGKILL the group: a detached group whose member traps TERM dies within the wait. `killAndWait(1, 0)` signals nothing (pid ≤ 1 is never a group Forge started). - B17. `isClaudeExecutable(word)`: `claude`, `claude.exe`, and an absolute path ending `/claude` or `\claude(.exe)` → true; a relative path (`./claude`, `bin/claude`) or another name → false. `hasBinary(cmd)` → whether `which` (`where` on Windows) finds it. `sleepSync(ms)` blocks for about `ms`. ## Edge and corner cases
- E1. EPERM is not proof of death: with `process.kill(pid, 0)` stubbed to throw EPERM, a dead holder keeps its lock (`withLock` times out, `lockHeld` → true), and so does a matching start time; a holder whose `startedAt` is 1 h off is still broken (ps proves reuse). Restore `process.kill` before anything else runs (synchronous test). Setup: POSIX; synchronous test; save `realKill = process.kill`, replace it with a function that throws `Object.assign(new Error('kill EPERM'), {code:'EPERM'})` when the signal is 0 and otherwise calls through; plant holders per the core.os recipe (dead pid; this pid with matching `startedAt`; this pid with `startedAt` 1 h earlier); `withLock(lock, () => true, {timeoutMs: 300})`; restore in `finally`. Old: test/lock.test.ts › "the lock proves death › EPERM is not proof of death"
- E2. A lock path that is a symlink to a directory (even one with mtime 10 min old) is never broken through: `withLock` times out, `lockHeld` → true, nothing is created inside the target, and the path stays a symlink. Setup: POSIX; `target = <scratch>/target` (`mkdirSync`, `utimesSync` to 10 min ago), `fs.symlinkSync(target, <scratch>/the.lock)`; afterwards `fs.readdirSync(target)` is `[]` and `lstat(lock).isSymbolicLink()` is true. Old: test/lock.test.ts › "the lock proves death › a lock path that is not a directory is never broken through"
- E3. `posixShell` on `win32` with no `where` answer and no bundled sh → `ForgeError` exit 1 whose message contains `POSIX sh`, `Git for Windows (Git Bash)`, `WSL2` and `SUPPORT_URL`. Setup: `posixShell({platform:'win32', env:{SHELL:'/usr/bin/bash', ProgramFiles:'D:\\Apps'}, where: () => null, exists: () => false})`. Old: test/platform.test.ts › "posixShell resolves sh per platform"
- E4. `versionAtLeast` with `''`, `git version`, `not a version`, `v2`, `2.` → false; a 10,000-digit line followed by `x` → false without hanging. Setup: none (pure); `[2, 38]` as the minimum. Old: test/platform.test.ts › "versionAtLeast and the git/gh minimums"
- E5. `run` timeout rounding: `timeoutMs` 300 → `1 s`, 1500 → `2 s`. Setup: pure `timedOutMessage('gh', ['api','user'], 300)` and `(…, 1500)`; the live timeout path uses `fakeBin` with a stub that sleeps 30 s and `run(stub, ['api','user'], {timeoutMs: 300})`, finishing in under 5 s. Old: test/gh.test.ts › "a hung gh times out"
- E6. `findOnPath` never searches the cwd: `PATH: 'rel-dir/bin'` (relative) → null even when the tool exists there. Setup: B13's stub `tool` placed in `<cwd>/rel-dir/bin` (relative PATH entry `path.join('rel-dir','bin')`). Old: test/release-strategy.test.ts › "findOnPath › findOnPath looks only at absolute PATH dirs"
- E7. `pidAlive(1)` is false although pid 1 exists (its group signal would be `kill(-1)`). Setup: none. Old: test/lock.test.ts › "pidAlive is false for pids that are not a real process id"
- E8. `writeAtomic` retries a planted temp name once, then refuses it, and a failed write leaves no temp file. A regular file at the first name → the write lands with the second name, the planted file is unchanged and no other `*.tmp` is left; `rand` returning the planted name twice → throws `code === 'EEXIST'`, `file` unchanged, no other `*.tmp`; a symlink at that name → the same `EEXIST` with its target untouched (POSIX). `file` a non-empty directory → the rename throws and no `*.tmp` is left in the parent. Setup: a temp dir; plant through the injected `rand` (e.g. `'a'.repeat(16)` then `'b'.repeat(16)`), never by mocking `crypto`. New: lib/core/os/fs.test.ts › "a planted temp name is retried once, then refused", "a failed write leaves no temp file"
- E9. `confinedDir(root, dir)` returns `dir`'s real path once every component from `root` down is a real directory, creating missing ones a level at a time, and never creates or writes through a planted parent. A link (`symlinkSync(outside, link, 'junction')`: a dir symlink on POSIX, a junction on Windows) at `root/verify` with `writeTextAtomic(root/verify/round-1.md, …, { root })`, a link at `root/review/round-1` under a real `review/` with `writeJsonAtomic(…/x.json, …, { root })`, and a regular file at `root/verify` each throw `/not a real directory/`, and `outside` stays empty (no file, no `round-1` dir). `writeJsonAtomic(root/a/b/c.json, data, { root })` creates `a/b` and writes the pretty-printed JSON; a file outside `root` throws `/is outside/`; `confinedDir(root, root)` is `realpath(root)`; a missing `root` throws `<root> does not exist`. Setup: `fs.realpathSync(fs.mkdtempSync(…))` scratch dir; `t.skip` only when `symlinkSync` throws `EPERM`. New: lib/core/os/fs.test.ts › "a confined write never goes through a planted parent"

## Regressions worth keeping
- R1. Locks used to be broken after 60 s of age, so a long critical section lost its lock to a waiter → only a provably dead holder is broken (B3, B4). Setup: B3 (`tryLock(lock)`, dir mtime set 10 min back with `utimesSync`, a lock-child waiter with `timeoutMs` 500); the waiter exits 1 with `held by pid <n>` on stderr and its log file is never created. Old: test/lock.test.ts › "the lock proves death › a section longer than the old 60 s limit keeps its lock"
- R2. Several waiters breaking one stale lock could each think they won → the `breaking` marker plus the token re-read admit one holder. Setup: B2 (a planted holder with a dead pid and token `dead-holder`, then four lock-child processes tagged a–d sharing one log). Old: test/lock.test.ts › "the lock proves death › two waiters on a stale lock: one holder"
- R3. A waiter that judged a holder dead and took over had its lock removed by the original holder's release → release is token-checked. Setup: B6 (inside `withLock`, overwrite holder.json with the same holder but `token:'someone-else'`; after `fn` the dir still exists with that token). Old: test/lock.test.ts › "the lock proves death › release only removes its own lock"
- R4. Under load, a child that exited before reading stdin reported EPIPE instead of its exit status → the status wins. Setup: B11 (1 MiB of `input` to `sh -c 'exit 3'`). Old: test/config-sinks-run.test.ts › "config sink commands › a command that exits without reading its stdin keeps its exit status"
- R5. Git Bash's MSYS `$SHELL` (`/usr/bin/bash`) broke spawn on Windows, and a bare `where`/`sh` could run a binary planted in the repo → SHELL ignored on win32, `where.exe` by absolute path with `$PATH:sh`. ## Cheapest layer
In-process for everything except: B2 (needs real separate processes: spawn `test/fixtures/lock-child.ts` four times with `execFile`), B15 (a real detached `sh` process group, POSIX), B11/B12 (real child processes; for B12 use `fakeBin` with a sleeping stub rather than `gh`), and the POSIX-only cases (pid reuse via `ps`, EPERM stub, symlinked lock path). B4's "dead pid" uses a real exited child pid (`spawnSync(process.execPath, ['-e',''])`.pid). No scratch git repo is needed anywhere in this unit.

## Setup recipes
- Lock scratch: `fs.realpathSync(fs.mkdtempSync(os.tmpdir() + '/forge-lock-'))`, lock path `<dir>/the.lock`.
- Planting a holder: `mkdir <lock>`, write `<lock>/holder.json` as `{v:1, pid, startedAt, host: os.hostname(), token:'planted-token'}`; this process's start is `new Date(Date.now() - process.uptime()*1000).toISOString()`; a reused pid is that minus 1 h. Age the dir with `fs.utimesSync(lock, t, t)` (61 s for the legacy rule, 10 min / 1 h for "never by age"). A `breaking` marker is `mkdir <lock>/breaking`.
- Contention child: `test/fixtures/lock-child.ts <lockDir> <log> <tag> [timeoutMs=20000] [holdMs=150]` appends `enter <tag>` / `exit <tag>` and exits 1 with the timeout message on stderr.
- Stubborn group (B15): `spawn('sh', ['-c', "trap '' TERM; sleep 60 </dev/null >/dev/null 2>&1 & exit 0"], {detached:true, stdio:'ignore'})`, wait for the leader's exit, then kill with grace 200 ms; always `process.kill(-pid, 'SIGKILL')` in `finally`.
- findOnPath stubs: write `#!/bin/sh\n` files with mode 0755 (and `<name>.CMD` on Windows); win32 cases are stat-only, so they run on any host by passing `'win32'`.
- Platform hosts: `{platform, arch:'x64', procVersion}` objects; the WSL string `Linux version 5.15.153.1-microsoft-standard-WSL2 (root@1234) (gcc (GCC) 11.2.0) #1 SMP`.
- posixShell injection: `where: (cmd) => found`, `exists: (p) => bool`, `env: {SHELL:'/usr/bin/bash', ProgramFiles:'D:\\Apps'}`.
- Clock jump (B8): save `Date.now`, set `Date.now = () => real() + 3*3600_000`, restore in `finally`.
