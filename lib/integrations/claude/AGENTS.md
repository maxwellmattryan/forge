# lib/integrations/claude/

Claude Code's command line, protocol, files and prices: the session argv and env, the stream-json protocol and the child that speaks it, transcripts and the model price table.

- `stream.ts` builds every line written to a session's stdin from fixed text or a fixed list: the one turn, permission answers (an allow echoes claude's own input), mode switches and a gate run's verdict retry. Nothing from requests, HTTP or config reaches one (docs/architecture/daemon-security.md). The two free-text lines are a chat's owner message and a child's brief (`briefLine`, one JSON-escaped line, capped at `BRIEF_MAX_CHARS`): a role child's, from `forge job step`'s brief, or a gate run's, from the CLI-built assist brief (`lib/office/foreman/attempt.ts`), each written by one caller only. Line caps (`maxLineBytes`, `STDERR_CAP`) apply there too. Redaction is the caller's job (`lib/office/session/log.ts` `logLine`, `forge job agent run`'s `onLine`): integrations can't import engine's known-secrets.
- `DENY_TOOLS` (then the caller's `deny`) and `PROMPT_TOOL` end every session argv, `scopedTools` swaps every file tool in `{allowedTools}` for one `Edit(//<root>/**)` rule per write root, and API keys are dropped unless `daemon.auth` is `api-key` (docs/architecture/daemon-security.md).
- `roleArgv` builds a role child's argv (`forge job agent run`), whose cwd is a job worktree: it takes absolute deny rules only and throws on any other, because a relative `DENY_TOOLS` entry would anchor at the worktree, and it passes `--setting-sources user --strict-mcp-config`, because the worktree's own `CLAUDE.md`, `.claude/settings*.json` and `.mcp.json` are files the branch's agents wrote and must not load as trusted. Its one system-prompt flag is `--append-system-prompt-file`, the trusted prefix `forge job agent run` passes (lib/engine/guard/prompt-prefix.ts), an absolute path only: a relative one or one holding NUL, CR or LF throws. Its `fork` option puts `--fork-session` straight after `--resume <id>` for a context session's fork (lib/engine/workspace/context-session.ts) and throws without a resume; a fork otherwise takes the same argv as a cold run. `stream.ts` emits one `first-request` event per stream (the first main-loop usage, never a subagent's), which `role.ts` returns as `firstRequest` beside the ok result's `text`: a fork's cache hit and a context's `READY` are read there. It also emits a `tool-use` event per main-loop assistant line with tool calls, which `role.ts` returns as `tools`, and counts the lines it could not read or act on (over the cap, not JSON, a protocol error) as `dropped`: a context child that called anything but `Read`, or dropped a line, is not ready. `role.ts` knows nothing of jobs and parses no claude output itself: it reads `ClaudeEvent`s, denies every permission prompt with `UNATTENDED_DENIED` unless its caller passes `onPermission`, and classifies a failure.
- `pricing.json` holds the model prices: take them from Anthropic's current pricing, never from memory, and bump `asOf`. `pricing()` and `/api/about` read it through `PLUGIN_ROOT`.
- Transcript paths come from job state only, which an agent or a checkout can write, so each id is checked before it becomes a path segment.
- `friction.ts` turns a located transcript into counts and a fenced-ready log; nothing from it but counts and keys leaves for `transcripts.json` (docs/IMPROVEMENT.md "Agent transcripts").
- Design: [Daemon security](../../../docs/architecture/daemon-security.md), [Daemon runtime](../../../docs/architecture/daemon-runtime.md).
