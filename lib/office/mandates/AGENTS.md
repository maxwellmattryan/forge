# lib/office/mandates/

Mandates: the owner's standing instructions to the Office, one file each in `.forge/runtime/mandates/`, written only by `forge mandate` (`lib/cli/commands/mandate.ts`).

- `store.ts` is the only reader and writer of the files. A file that can't be read safely is unreadable with a `problem`, and nothing acts on it: narrowing fails closed.
- A mandate's `decides` only ever narrows `foreman.decides`: `checkForemanDecision` and `gateOwner` (`lib/office/foreman.ts`) and `forge job assist` read it through `jobMandateDecides`, and the milestone-approval gate through `mandateDecides`. Engine code can't import this module, so `assistantBrief` takes the mandate as a parameter.
- A goal mandate's ready draft waits at the `milestone-approval` gate (`gate.ts`): its status, its owner, the job-less gate request `forge mandate draft record` queues for an assistant foreman, the assistant's brief, and `decideDraft`, the one decision path the CLI and the dashboard share. Who decides is `checkMandateGateDecision` in `lib/office/foreman.ts`. Approve files the draft through `filing.ts`, which writes `<id>/filing.json` before and after each tracker call (versioned in `lib/core/versions/filing.ts`) and ends by setting the mandate's `filedAt` and scope.
- The body is the owner's free text: it reaches a brief or `forge mandate show` only through `mandateGuidance` (`fenceImport`), never raw. A goal mandate's goal is the same: only through `mandateGoal`, and `store.ts` writes it as one JSON-quoted line, last.
- A goal mandate's drafting runs keep their files in its runtime dir `<id>/` (`mandateDir`): `survey.md` (`intake.ts`), `ledger.jsonl` and `draft.json` (`draft.ts`), `filing.json` (`filing.ts`), all written by the CLI under real directories. The drafter's staging file is the one file outside it, `<worktrees.root>/_office/drafts/<id>.json`, read only through `readRegular`. `draft.ts` holds every draft rule; `draft.json` is versioned in `lib/core/versions/draft.ts`.
- Only the Office pass (`pass.ts`, `forge office pass`) pauses or closes a mandate on its own, through `writeMandate` with the foreman as the actor, and only while the mandate still has the status and `updatedAt` it read. An `until: released` mandate whose work is done waits for its release instead: the pass plans it through `lib/engine/release/mandate.ts` (never runs it), applies no budget pause or stall meanwhile, and closes the mandate once the release run finished; `mandateReleaseRefusal` in `lib/office/foreman.ts` is the mandate's policy for that release. `progress.ts` reads a mandate's jobs from the CLI records and the archive (never a job folder's `job.json` or `events.jsonl`); the pass, `forge office survey|start` and `forge mandate show` all compute from it.
- Every choice of the office session and every enforcement of the pass is a directive (`directives.ts`): a `directive` event in the repo audit log, and on the job it names. `director.ts` holds `forge office survey|board|start|resume|note`; `start` and `resume` re-check every limit under the office lock (`withOfficeLock`).
- Design: [Foreman](../../../docs/architecture/foreman.md).

| File | What it holds |
|---|---|
| `cadence.ts` | When the pool runs the Office pass (`forge office pass`, ./pass.ts): every `foreman.cadence` minutes, at start, when a mandate file changes and when a job in a mandate settles. |
| `contract.ts` | The mandate contract's rules: the stored shape a file needs to be read, the refusals of `forge mandate new\|edit`, the defaults a new mandate takes, the contract as it applies under the config (what it caps), the derived state and chain, and the guidance and goal fences. |
| `directives.ts` | Directives: the director loop's record, one `directive` event per choice the office session makes (start, resume, note, skip) and per enforcement the Office pass applies (pause, close, stall, park, cancel). |
| `director.ts` | The director turn's CLI side: `forge office survey\|board\|start\|resume\|note`, which the office session runs on a `direct` request (and a person may run in their own terminal). |
| `draft.ts` | A goal mandate's milestone draft and its drafting runs' records: the draft rules (draftProblems), the stored `.forge/runtime/mandates/<id>/draft.json` (readDraft, recordDraft), the drafter's staging file under the office session's worktrees root, the draft requests for a mandate, the spend ledger (`ledger.jsonl`), and the status `forge mandate draft show` prints. |
| `filing.ts` | Filing an approved milestone draft: the pre-flight checks that run before any write, the exact text the secret scan and the tracker both see, and the filing record (`.forge/runtime/mandates/<id>/filing.json`), written before the first tracker call and after each, so a stopped filing resumes without filing anything twice. |
| `gate.ts` | The milestone-approval gate over a goal mandate's ready draft: its status, who owns it, the gate request a recorded draft queues for an assistant foreman, the assistant's brief (`forge mandate draft assist`), and the one decision path (`decideDraft`) the CLI and the dashboard both call, with the daemon refusal, the request and digest pins and a per-mandate lock. |
| `intake.ts` | Intake's first CLI call: `forge mandate draft prepare` writes a goal mandate's survey (`.forge/runtime/mandates/<id>/survey.md`, outside every session's write roots) and returns the `forge:drafter` brief. |
| `pass.ts` | The Office pass (`forge office pass`, which `forge dash` runs every foreman.cadence minutes and on events): deterministic code, no model, that enforces each mandate's contract. |
| `progress.ts` | A mandate's progress, which the Office pass enforces and `forge office survey\|start` and `forge mandate show` read: its jobs and how each stands against its `until`, its spend and starts, the scope items the tracker lists for it, the candidates and the window the Foreman may start from, why it is blocked, and its stalls. |
| `store.ts` | Mandate files: `.forge/runtime/mandates/<id>.md`, YAML frontmatter then the owner's guidance. |
| `types.ts` | The mandate shapes, type-only: the file `forge mandate` writes, the contract terms, the summary and state the CLI prints, and a goal mandate's milestone draft. |
